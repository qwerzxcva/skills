# 上下文压缩与记忆治理规程

## 一、三层结构（先分清在哪一层）

| 层 | 内容 | 生命周期 | 载体 |
|---|---|---|---|
| L1 工作集 | 当前任务原文、代码、报错、指令 | 本任务 | 上下文窗口 |
| L2 会话摘要 | 目标、决策、未决问题、关键实体 | 一次会话 | 会话级摘要 |
| L3 长期记忆 | 稳定偏好、事实、约定、术语 | 跨会话 | memory 库 |

**铁律：L1 不写进 L3。** 中间产物（日志、试错、临时路径）不属于记忆。

## 二、压缩触发

- **不预设固定阈值**，按应用当前压缩设置为准；用户已明确删除固定阈值设定，不得自行恢复数字。
- 接近上限时按序压缩：① 删重复 ② 压过程（多步操作 → 一句结果）③ 抽象（原文 → 规则/结论）④ 最后才丢细节。
- 不可压的三类：用户明确指令、验收标准、未完成待办。丢了就是事故。
- 主动整理时机：一个子任务收口时、一次长工具链结束时，而不是等到被截断。

## 三、上下文卫生（源用户实测偏好）

- 长工作流（大范围调研、批量定位、多文件核对）**一律派子代理**，单次并发 ≤2。
- 子代理**只回报结论与关键「文件:行号」**，不复述原文。
- 多个独立只读操作**合并进一次调用**，一次性拿齐，不要多轮往返。
- **已核实的事实直接引用**，不重读重证。
- 膨胀严重时把约束固化进项目根 `AGENTS.md`，不靠换更大窗口的模型。

## 四、记忆分类（六类）

事实 / 偏好 / 决策 / 约束 / 待办 / 术语。说不清归哪类 → 多半不该记。

## 五、记忆写作规范

- 一条一事实。
- 必须含**条件**（"要求简短，技术细节除外"而非"喜欢简短"）。
- 必须含**来源/时间**。
- 可执行句，不堆形容词。
- **覆盖优于追加**：同主题新值覆盖旧条目并标时间，不并存矛盾记忆。
- 写入前先检索已有记忆，命中则合并。

## 六、摘要模板

```
目标：<一句话>
已定决策：<决策 → 理由>
产出物：<文件/结论的实际位置>
未决问题：<问题 → 卡在哪>
下一步：<可直接执行的动作>
关键实体：<人名/包名/路径/术语 → 含义>
```

不许写"进行了深入讨论""取得良好进展"。

## 七、投放优先级

约束 > 决策 > 偏好 > 事实 > 术语 > 待办。**约束永远第一个进上下文。**
长上下文只投最相关的一窗；检索无结果时明说"无相关记忆"，禁止虚构过往对话。

## 八、自检清单

- [ ] 每条记忆能归入六类之一
- [ ] 没有把过程性内容写进长期记忆
- [ ] 同主题无矛盾记录
- [ ] 每条含条件或来源
- [ ] 摘要含"未决问题"与"下一步"
- [ ] 未自行设定压缩阈值数字
