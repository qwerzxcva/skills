# 股票数据工程规程

## 一、云端数据库拓扑（存量事实，改动前先对齐）

| 仓库 | 内容 |
|---|---|
| db-daily-0..5 | A股日线分片（6 片） |
| db-fin-0 | 财务全史（约 38 年） |
| db-min-0/1 | 5 分钟线，按月分区，2020 起 |
| db-hk-0 | 港股（约 2072 票） |
| t8-fq | A股与 ETF 前复权日线全史（qfq parquet） |

主库已回补 +70,935 行 / +381 票（新鲜票 1803→2179），增量以主库为准。

## 二、口径纪律（踩过的坑，不许再踩）

1. **px_view 必须幂等**：重复 attach 不得产生重复行；必须含全 OHLC 列；序列化 `json default=str`（否则日期/Decimal 报错）。
2. **前复权统一走 px_view**，不要在脚本里各自算复权因子。
3. **date 列统一 DATE 类型**（历史上因此把 15GB 压到 7.5GB）。
4. 因子矩阵与行情表日期键必须同类型才能 join，参与前先 `DESCRIBE`。

## 三、增量与断点

- 每个采集任务必须有**进度标记文件**（如 `_done_flow.txt`，记录 2084/4885），中断后从标记续跑，不从头重来。
- 资金流类需标明已完成票数与总票数，并给出缺口清单。
- 采集完成写 `_done_*.txt` 后，才允许进入下一阶段（防止半成品被下游消费）。

## 四、内存控制（最常翻车处）

- 大矩阵写入 DuckDB **必须逐批 INSERT + CHECKPOINT**；一次性 `concat` + 全量写入会被 OOM killer 杀。
- 逐票读取、逐批写入；单批行数按内存上限定，宁小勿大。
- 需要 4.8GB 级矩阵时先估算：行数 × 列数 × 8 字节，超过可用内存一半就分段。

## 五、推送 GitHub 纪律

- 固定顺序 `put(repo, tok, path, local)`——参数顺序错会导致推到错误仓库。
- **token 绝不写入 heredoc 或日志**：运行时会替换成掩码串，导致推送静默失败；正确做法是写脚本文件再执行，token 从环境读取。
- 校验 token 用 `ghp_[A-Za-z0-9]{30,}` 排除被掩码的串。
- 推送前 `git ls-remote` 确认目标仓存在与权限。

- [ ] 缺口清单为空，或缺口有明确原因
- [ ] date 类型为 DATE，与下游一致
- [ ] 断点文件已更新
- [ ] 推送成功且远端行数回读一致
