# 移动端签名 / 打包 / 上架 / 合规要点

## 签名

| 平台 | 签名 | 要点 |
|---|---|---|
| iOS | 开发者证书 + Provisioning Profile | 区分开发/分发证书，团队共享用企业证书 |
| Android | keystore 签名 | keystore 妥善保管，丢失无法更新 App |

## 打包

- **iOS**：Archive → 上传 App Store Connect → TestFlight 测试。
- **Android**：生成 AAB（Google Play 要求）→ 各商店分发。

## 商店审核要点（App Store / 各安卓商店）

| 审核点 | 说明 |
|---|---|
| 隐私政策 | 必须有隐私政策 URL，说明数据收集用途 |
| 权限声明 | 申请的权限要有明确用途，不滥用 |
| 账号删除 | App 内注册的账号须提供注销入口（苹果强制） |
| 内容合规 | 涉金融/医疗等需资质 |

## 隐私合规（中国区重点）

- **个人信息保护法（PIPL）**：收集最小必要，明示同意。
- **隐私政策 + 用户协议**：首次启动弹窗 + 同意。
- **敏感权限**：定位/相机/通讯录须运行时申请 + 用途说明。
- **SDK 合规**：第三方 SDK（统计/推送）须在隐私政策披露。

## 金融/车联网附加要求

- **金融 App**：须有相关金融业务资质，数据加密存储，交易留痕。
- **车联网 App**：位置数据敏感，须单独授权与脱敏。

## 上线前自检清单

1. 签名证书配置正确。
2. 隐私政策 URL 可访问。
3. 权限清单与用途说明齐全。
4. 敏感数据（密钥/用户信息）无硬编码、无明文存储。
5. 测试账号/接口地址无残留。

## 常见反模式

- ❌ 隐私政策缺失或敷衍
- ❌ 权限一次申请一堆
- ❌ keystore 提交到仓库
- ❌ 生产环境配置泄漏到安装包
