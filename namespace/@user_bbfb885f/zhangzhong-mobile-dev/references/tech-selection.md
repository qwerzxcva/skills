# 移动端技术选型决策矩阵

## 原生 vs 跨端对比

| 维度 | 原生（Swift/Kotlin） | 跨端（Flutter/RN） |
|---|---|---|
| 性能 | 最佳 | 良好（接近原生） |
| 开发效率 | 双端各写一套 | 一套代码双端 |
| 团队要求 | 需双端工程师 | 前端即可上手 |
| 原生能力 | 完全 | 需插件/桥接 |
| 生态成熟度 | 最成熟 | Flutter/RN 成熟 |
| 包体积 | 小 | 偏大（跨端运行时） |
| 复杂动画/游戏 | 最佳 | Flutter 强，RN 弱 |

## 选型决策规则

**选原生**：
- 强依赖原生能力（AR、深度相机、蓝牙、高性能渲染）
- 对性能/包体积极致要求
- 已有双端原生团队

**选 Flutter**：
- 双端同时上线、UI 一致性要求高
- 团队前端背景、追求开发效率
- 需要复杂动画/自绘 UI

**选 React Native**：
- 团队强 React 背景
- 与现有 Web 共享技术栈
- 需要热更新（CodePush 等）

## 快速决策清单

1. 是否强依赖原生硬件能力？→ 是则原生
2. 是否双端同时上线？→ 是则考虑跨端
3. 团队是什么技术背景？→ 前端→Flutter/RN，原生→原生
4. 对性能和包体积是否极致敏感？→ 是则原生

## 金融/车联网场景提示

- **金融**：安全要求高，密钥/敏感数据用原生安全存储（Keychain/Keystore），跨端需用原生桥接。
- **车联网**：蓝牙/定位/传感器高频，优先原生或 Flutter（性能更好）。

## 常见反模式

- ❌ 不分析需求就"我们只用 XXX"
- ❌ 团队不会 Dart 硬上 Flutter
- ❌ 追求"一套代码"忽略原生能力依赖
