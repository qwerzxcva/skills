# 掌中 · 移动端原生与跨端开发

> 移动 App 从选型到上架的全流程方法：原生还是跨端不再拍脑袋，架构、原生能力、发布合规一站搞定。

**金融/车联网移动端友好 · MIT 可商用**

## 为什么需要它

做移动 App 最容易在起点就踩坑：

- **选型纠结**：原生（Swift/Kotlin）还是跨端（Flutter/RN）？团队吵一个月没结论。
- **架构散乱**：页面里堆业务逻辑，改一个功能牵一发动全身。
- **上架被拒**：隐私政策缺失、权限滥用，提交了几次都被打回。

这个 skill 用「选型 → 架构 → 开发 → 测试 → 发布」全流程，把关键决策显式化。

## 它能做什么

- **选型决策**：按性能/团队栈/迭代速度/原生能力依赖，给原生 vs 跨端结论。
- **架构设计**：分层架构 + 状态管理选型（SwiftUI/Compose/Riverpod）。
- **原生能力接入**：推送/定位/相机/支付/安全存储的接入与权限要点。
- **测试适配**：单元/UI/真机测试，多分辨率、刘海屏、深色模式。
- **发布合规**：签名、打包、隐私政策、商店审核要点。

## 真实示例

**输入**：`我们要做一个车险理赔 App，双端，团队主要熟前端，该选什么技术栈？`

**输出**（节选）：

```
选型结论：Flutter（跨端）
理由：双端需同时上线、团队前端为主（Dart 上手快）、
     理赔功能多为表单+拍照上传，无需深度原生性能。

架构建议：
lib/
  features/       # 按业务域划分（报案/拍照定损/进度查询）
  core/           # 网络/存储/路由/依赖注入
状态管理：Riverpod（单一数据流，便于测试）

安全红线：保单/银行卡信息用 Keychain/Keystore 存储，禁止硬编码
```
