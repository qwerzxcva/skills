## 0. 30 秒速查卡（不会用先看这段）

### 0.1 什么时候它会自己跑

| 场景 | 会发生什么 | 你要做什么 |
|---|---|---|
| **改了云总纲** | 小Y 对话内自动把总纲内容同步到备份文件 | **什么都不用做**，等结果反馈 |
| **每天 12:00** | 自动化检查总纲/06-09 与各自备份是否一致，并以云端为基准覆盖本地 | 看报告，不一致会告警并自动修复 |
| **刚迁移/初始化完** | 运行一次校验脚本 | 跑一次 `sync_backup.py`，看到 ✅ 即可 |
| **断网后恢复联网** | 本地可能落后 | 手动跑一次脚本补校验 |
| **换电脑登录同一账号** | 触发「一键自检」从乐享 06-09 拉回本地 4 文件，配置/标记自动共享 | 说一句"一键自检"即可，不用手动拷文件 |

> **一句话总结**：总纲改完自动备份，日常不用管脚本；只有初始化、断网恢复、怀疑异常时才需要手动跑一次。

### 0.2 第一次用，三步走

1. 把技能包放进 `~/.workbuddy/skills/memory-cross-device-sync__skillhub/`。
2. **运行一次校验脚本**：
   ```bash
   python ~/.workbuddy/skills/memory-cross-device-sync__skillhub/scripts/sync_backup.py
   ```
3. 看到 `✅ 校验通过` 即完成。

**关于配置**：v2.0 起多数参数会自动探测（drive_id、同步盘镜像路径等）。只有老用户如果已有《8.workbuddy.memory》等旧文件夹，推荐在 `config.json` 里填一下 `cloud_folder_id` 直接复用；新用户完全不用填。

### 0.3 5 个使用技巧

1. **总纲改完不用动**：小Y 每次改完云《工作习惯总纲》，会自动把内容刷新到《工作习惯总纲_备份》，并在回复里告诉你版本号是否一致。
2. **每天看一次自动化报告**：每天 12:00 自动化（首次激活本技能时由小Y 自动创建，不写死本机 ID）会检查总纲与 06-09 主备、并以云端覆盖本地，没告警就是正常。
3. **换电脑不重新配**：同一 Windows 用户 + 同一 WPS 账号下，`.workbuddy` 目录和云总纲天然共享。
4. **断网恢复后跑一次**：如果断网期间改了本地记忆文件，联网后跑一次脚本做健康检查。
5. **怀疑异常先跑脚本**：看到总纲/备份版本号不一致，或记忆行为没生效，先跑 `sync_backup.py` 看清单。

## 1. 它是干什么的

### 1.1 核心定位（最重要）

本技能的首要功能**随架构升级（2026-08-22）已变更**：从「本地改→三端双写」改为「云端工作习惯总纲为唯一权威，本地只留指针，总纲变更必同步备份」。

> **架构背景**：工作习惯与行为规则已统一收进云端《工作习惯总纲》作为全局行为规则权威。本地 `~/.workbuddy/MEMORY.md` 仅保留指向该云文件的指针段 + 事实性记忆，不再承载规则全量。SessionStart 钩子保证**每会话开头** Read 云总纲一次（读的时机口径见 §1.1.0）。

### 1.1.0 读总纲时机口径（v2.0.10 修正，与云总纲第七章、IDENTITY.md 一致）

> 修正背景：旧版 SKILL.md 写「每轮 Read 云总纲」，与现行架构冲突——IDENTITY.md 收尾段已每轮常驻注入云总纲兜底，MEMORY.md 指针段亦明确「普通问答轮次无需全量重读」。来源：备忘录《2026年备忘录》板块五 5.2 待更新清单（用户 2026-08-27 指出）。

| 时机 | 是否读 | 怎么做 |
|---|---|---|
| 每会话开头 | 必读一次 | 用 MCP 文档读取工具读乐享《工作习惯总纲》；读后当轮回复明确反馈「我已阅读云总纲」，本会话内不再强制每轮反馈 |
| 会话内后续轮次 | 不重读 | IDENTITY.md 收尾段常驻注入作离线兜底；普通问答靠它即可，不重复拉全文 |
| 外部可见动作前 | 补读最新版 | 写/建/改云端文件、归档、发布、文件夹命名等错难收回的动作，动手前必先读回最新版再执行 |
| 用户告知已改总纲 | 补读最新版 | 用户说改了总纲，当轮先读回最新版，再按新版执行 |

> 一句话：**每会话读一次 + 外部动作前补读，普通问答轮次不重读。**

### 1.1.1 云后端切换（v2.0.3 起，硬执行）

本技能的云端读写载体按**全局偏好 `cloud_default`**（写在 `~/.workbuddy/MEMORY.md`）动态选择，不再写死 WPS：

- **默认后端 = 乐享知识库（lexiang 连接器，已连接）**。除非用户明确说"用 WPS 云文档 / kdocs 归档 / 存金山文档"，否则总纲读取、备份刷新、事实记忆同步一律走乐享分支（第 1.1.2 节乐享工具映射）。
- **用户明确说 WPS** → 走 WPS kdocs 分支（沿用旧 WPS 总纲/备份 file_id，由用户本地 config 提供，不写死）。
- **用户说两边都归档 / 乐享和 WPS 都存** → 双写（乐享 + WPS 都执行，以乐享为权威、WPS 为镜像）。
- 偏好持久生效：说一次、后续都按此，直到用户再次切换。切换后同步更新 MEMORY.md 的 `cloud_default`（lexiang / wps / both 三态）。

**乐享工具映射（替代原 kdocs 调用）**：
- 读总纲/备份 → `entry_describe_ai_parse_content`（page 正文）或 `entry_import_content_to_entry` 回读；
- 写/刷备份 → `entry_import_content`（新建 page）或 `entry_import_content_to_entry`（写入已有 page）；
- 取真实 id → `search_kb_search` + `entry_list_children` + `space_describe_space`（不写死 id）；
- 校验可读 → `whoami` 确认连接/v2。

> 乐享《工作习惯总纲》《工作习惯总纲_备份》《8.workbuddy.memory》均落在你的乐享个人知识库（非 WPS 云文档），本技能所有 id 实时取，不记死。

- **云端为单一真相**：习惯/规则的修改只发生在云端《工作习惯总纲》，本地不存规则副本，因此不再需要「本地改→双写云端」的旧逻辑。
- **指针一致性校验**：脚本仅校验本地 MEMORY.md 指针段声明的乐享 entry_id 与云端总纲是否对应、可读；指针几乎不变，校验极轻。
- **总纲改后必同步备份**：云端《工作习惯总纲》每次修改后，必须将完整内容同步刷新到《工作习惯总纲_备份》（乐享 entry_id **实时解析**，按 §16「ID 动态获取流程」用 `whoami` → `lexiang_search` 取当前用户真实值，正文与脚本均不写死），防止主文件丢失/损坏造成不可逆损失。**这是本技能在新架构下最核心的职责——保证总纲与备份始终同步，否则权威规则失去兜底。**
- **改完必告知用户**：备份刷新结果（总纲版本、备份版本、一致性）必须反馈，不静默。
- **06-09 身份/记忆文件双写（云端为基准，2026-08-25 新增）**：IDENTITY/SOUL/USER/MEMORY 是 WorkBuddy 框架启动必须读的本地文件，不能纯云端化。对话内修改其中任一 → 立即双写本地真身 + 乐享主文件(06-09) + 乐享备份页（「身份记忆备份区」），sha1 全文比对并反馈用户；每日 12:00 自动化以云端为基准覆盖本地（云覆盖本地），分叉时共同写入不同点、相同点不动。与总纲同源等效，非纯指针。
- **历史双写逻辑已退役**：旧的三端（本地/镜像/云端）全量双写仅适用于「本地存规则全量」的旧时代，现已不再需要；相关兜底自动化（每日 21:00 三端校验）已取消。

### 1.2 能做什么

- 同步 `~/.workbuddy/` 下的 `MEMORY.md`、`IDENTITY.md`、`USER.md`、`SOUL.md`（记忆 + 身份/工作习惯设定）。
- **不同步任何技能文件**：`~/.workbuddy/skills/` 下的 `SKILL.md` 一律不纳入——技能是独立资产，归 `7.workbuddy.skill` 管，不进记忆云文件夹（详见第 1.3、第 4 节与铁律）。
- 首次运行自动探测并复用你已有的云端记忆文件夹，不重复建。
- 三端（本地 / 同步盘镜像 / 云端）一致性校验，不一致自动重试。
- 同步前自动备份、旧备份自动轮转清理。
- 同步完成后可选触发靠谱助手做行为基线重校验。

### 1.3 不能做什么（边界，用前看清）

- **不是网盘**：只同步配置清单里的几个个性化文件，不会同步整个 `.workbuddy` 目录。
- **不能跨 WPS 账号**：两台电脑必须用同一个 WPS 账号、同一个 WorkBuddy 账号，否则永远对不上。
- **不能离线同步**：断网时只能写本地和镜像，云端会落后；联网后需再跑一次脚本补上。
- **不能自动解决真冲突**：如果本地、云端、镜像三端内容各不相同（你在两台电脑改了同一处），脚本会停下来告诉你，由你决定怎么合并。
- **不保证 WPS 客户端不捣乱**：WPS 桌面客户端可能把云端旧版拉回本地覆盖新版。脚本能检测并尝试恢复，但最彻底的做法是把这个云端文件夹从 WPS 客户端的同步列表里排除（见第 6 节）。
- **不能移动云端文件夹**：kdocs-cli 的 `move-file` 只支持移动文件，不支持移动文件夹。如果你需要整理云端文件夹结构，请在 WPS 网页端操作。

## 2. 常见问题与反模式（先看这里，少踩坑）

### 2.1 新手最常踩的 5 个坑

> 说明：以下 5 个坑与 `drive_id` / `sync_mirror` / `kdocs-cli` 相关，均属**旧 WPS 后端分支**的专属问题。**默认后端=乐享知识库时不会触发**（乐享走 lexiang 连接器、id 实时取、无需填 drive_id）。仅当用户明确选择 WPS 后端时才需参考本表。

| 坑 | 现象 | 解决 |
|---|---|---|
| **① 以为要手动备份** | 总纲改完不知道跑没跑备份 | 看小Y 回复里有没有「总纲与备份一致」反馈；没反馈就手动跑一次 `sync_backup.py` |
| **② 没填 drive_id** | 运行后提示「未配置 drive_id」 | v2.0 起脚本会**自动探测** `drive_id`，首次运行多数无需手填；若探测失败（如 kdocs-cli 未登录），再去 WorkBuddy 的 kdocs 连接器配置里找 `drive_id` 填到 `config.json` |
| **③ sync_mirror 找不到** | 提示「找不到 WPS 同步盘镜像目录」 | 打开 WPS 客户端，右键记忆文件夹 →「打开文件所在位置」，把路径填到 `config.json` 的 `sync_mirror` |
| **④ 只改本地不跑脚本** | 另一台电脑看不到更新 | 改了 MEMORY.md 等文件后，**立即**运行一次脚本，不要等 WPS 客户端自动同步 |
| **⑤ 两台电脑改了同一处** | 提示「出现真冲突」 | 脚本会停下来，手动比对本地/云端/镜像后决定保留哪边 |

### 2.2 报错信息速查
> 说明：下表报错均源自 kdocs-cli / drive_id / WPS 同步盘，属**旧 WPS 后端分支**。默认乐享后端不会产出这些报错；仅 WPS 分支用户参考。

| 报错 | 白话解释 | 你该做什么 |
|---|---|---|
| `找不到 kdocs-cli` | 脚本找不到云文档命令行工具 | 检查技能包 `bin/kdocs-cli` 是否完整（完整版）；或自行安装并加入 PATH（纯净版） |
| `未配置 drive_id` | 不知道往哪个 WPS 云盘写 | 填 `drive_id`，来源：WorkBuddy kdocs 连接器配置 |
| `找不到 WPS 同步盘镜像目录` | 三端校验需要本地镜像路径，但脚本没找到 | 按 0.2 第 2 步，手动把镜像路径填到 `sync_mirror` |
| `创建云端文件失败` | 上传没成功 | 常见原因：kdocs-cli 未登录、drive_id 填错、文件名含非法字符、网络异常。先运行 `kdocs-cli login`，再检查 `drive_id` |
| `本地被云端旧版覆盖` | WPS 客户端把旧版拉下来盖掉了本地新版 | 脚本会尝试从备份自动恢复；恢复后会把新版重新推上云 |
| `三端内容各不相同` | 本地、云端、镜像各有各的版本 | 脚本无法自动合并，需要你手动比对后保留正确版本，再跑脚本 |
| `400100 参数错误` | WPS 接口拒绝了这个请求 | 常见原因：文件名含 `/《》` 等特殊字符；云端 folder 对象异常。检查文件名或换网页端操作 |

### 2.3 FAQ

**Q1：总纲修改后到底要不要手动跑脚本？**
A：不需要。小Y 在对话内改完总纲会立即自动刷新备份，并在回复里反馈版本号。只有在断网、自动化失效或你怀疑异常时，才手动跑 `sync_backup.py` 校验。

**Q2：运行后提示"找不到 WPS 同步盘镜像目录"怎么办？**
> 注：此 Q 仅适用于明确选择 WPS 后端的用户。默认乐享后端无需 sync_mirror，不会出现该提示。
A：打开 WPS 客户端，找到《workbuddy.memory》（或《8.workbuddy.memory》）文件夹，右键"打开文件所在位置"，把路径填到 `config.json` 的 `sync_mirror` 里。路径类似：
```
C:/Users/你的用户名/Documents/WPSDrive/xxx/WPS云盘/.../workbuddy.memory
```

**Q3：提示"未配置 drive_id"怎么办？**
> 注：此 Q 仅适用于明确选择 WPS 后端的用户。默认乐享后端不依赖 drive_id。
A：v2.0 起脚本会在首次运行时自动探测 `drive_id`（依赖 kdocs-cli 已登录）。若自动探测失败（最常见原因是 kdocs-cli 未登录），先运行 `kdocs-cli login` 授权，再填 `drive_id` 到 `config.json`。如果还没连 WPS 云文档，先授权连接。

**Q4：为什么同步完三端还是不一致？**
A：脚本会自动重试一次。如果还不一致，常见原因：
- 网络抖动，等几秒再跑一次。
- kdocs-cli 上传动作名为 `upload-new-file` / `upload-replace-file`（带连字符，脚本兜底通道已按此调用）；若自装版本报 `unknown action`，即动作名不符。完整功能版已内置 2.5.27，兜底通道正常，无需关心版本。
- WPS 客户端正在同步，造成镜像被改写。可暂时退出 WPS 客户端再跑脚本。

**Q5：备份文件占空间吗？**
A：默认每个文件只保留最近 10 份，且超过 90 天的旧备份会自动清理。如果你很少改记忆文件，10 份也占不了多少空间。

**Q6：两台电脑记忆不同怎么办？**
A：先确认两台电脑登录的是同一个 WPS 账号和同一个 WorkBuddy 账号。然后每天固定时间跑一次本脚本。如果两边都改了同一处，脚本会停下来问你，由你决定保留哪边。

**Q7：我不想让 WPS 客户端自动同步记忆文件夹，怎么排除？**
> 注：此 Q 仅适用于明确选择 WPS 后端的用户。默认乐享后端不走 WPS 客户端，无此问题。
A：在 WPS 客户端的同步设置里，找到《workbuddy.memory》文件夹，选择"不同步"或"移除本地同步"。这样只有本技能会通过 kdocs-cli 主动读写云端。

**Q8：怎么只清理旧备份，不做同步？**
A：运行 `python .../memory_sync.py --cleanup-only`。

## 4. 同步清单（v2.0 新架构）

新架构下，规则权威在云端，本地只留指针，因此"同步清单"从「全量文件双写」变为「指针校验 + 总纲备份同步」两项职责：

1. **本地指针校验**：`~/.workbuddy/MEMORY.md` 顶部指针段声明的乐享云总纲 entry_id（**动态提取**，由 `scripts/sync_backup.py` 按上下文锚定 `《工作习惯总纲》…entry_id` 解析，详见 §10 + 脚本 `extract_pointer_ids()`）必须存在且可读；指针段未被误删、entry_id 未被改错。脚本不写死任何具体 id，跨用户/跨空间天然安全。

3. **事实性记忆（本地 MEMORY.md）**：本地资产、本地为编辑原点，但通过第 4 项 06-09 双写镜像到乐享 09.MEMORY（云端为基准，分叉时共同写入不同点）。与总纲分开，不混入以免臃肿。
4. **06-09 双写（云端为基准，2026-08-25 新增；乐享落点三分区 2026-08-26 明确）**：IDENTITY/SOUL/USER/MEMORY 本地真身 ↔ 乐享主文件，按"云端为基准的双向双写镜像"同步——对话内改完即双写本地+云主+云备份，sha1 全文比对并反馈；每日 12:00 自动化（首次激活本技能时由小Y 自动创建，不写死本机 ID）以云端覆盖本地（云覆盖本地），分叉时共同写入不同点、相同点不动。乐享落点严格三分区（详见第 3.2 节）：① **主文件**——《工作习惯总纲》+ IDENTITY/SOUL/USER/MEMORY 统一置于《8.workbuddy.memory》**根目录**；② **备份页**——06.IDENTITY_备份 / 07.SOUL_备份 / 08.USER_备份 / 09.MEMORY_备份 统一置于《8.workbuddy.memory》下的「身份记忆备份区」；③ **历史/旧版**——历史版本、【历史版本】等统一置于「256.【历史文档】」（位于「WorkBuddy 专业文件」根目录，space：涂腾的个人知识库）。三区严格隔离，互不混入。

## 5. 配置说明（config.json）
> 说明：以下 `drive_id` / `sync_mirror` / `cloud_folder_id` 等字段均属**旧 WPS 后端分支**配置。默认乐享后端零配置即可（id 实时取），无需填写；仅当用户切换至 WPS 后端时才按此配置。

```json
{
  "drive_id": "自动探测，一般不用填",
  "parent_id": "",
  "cloud_folder_id": "老用户推荐填：已有记忆文件夹的 file_id",
  "cloud_folder_name": "workbuddy.memory",
  "scan_max_depth": 3,
  "sync_mirror": "自动探测，一般不用填",
  "auto_create": true,
  "backup_keep_count": 10,
  "backup_max_age_days": 90,
  "conflict_strategy": "ask",
  "kaopu_enabled": false,
  "kaopu_command": "workbuddy run-skill kaopu-assistant-init",
  "items": [
    {"name": "MEMORY.md",   "rel": ".workbuddy/MEMORY.md",   "fmt": "md"},
    {"name": "IDENTITY.md", "rel": ".workbuddy/IDENTITY.md", "fmt": "md"},
    {"name": "USER.md",     "rel": ".workbuddy/USER.md",     "fmt": "md"},
    {"name": "SOUL.md",     "rel": ".workbuddy/SOUL.md",     "fmt": "md"}
  ]
}
```

**零配置原则**：
- `drive_id`、`sync_mirror`：脚本首次运行会自动探测，多数用户不用填。
- `cloud_folder_id`：**老用户推荐填**。如果你已有《8.workbuddy.memory》等旧文件夹，填了就直接复用，不再遍历探测。
- 其余项都有默认值，首次使用无需修改。

**字段说明**：
- `drive_id`：WPS 云文档的 drive_id。自动探测失败时才需手填。
- `sync_mirror`：WPS 同步盘在本机的镜像目录。自动探测失败时才需手填。
- `cloud_folder_id`：老用户强烈推荐填写，直接复用已有文件夹。
- `backup_keep_count`：每个文件保留几份备份，默认 10。超出的旧备份自动删。
- `backup_max_age_days`：备份超过多少天自动清理，默认 90 天。设为 0 可关闭按时间清理。
- `conflict_strategy`：真冲突时策略。默认 `ask`（停等用户），可选 `cloud`（以云端为准，慎用）。
- `kaopu_enabled`：是否同步完成后触发靠谱助手做基线重校验。默认 false。

## 6. 防覆盖说明（重要，血的教训）
> 说明：本节所述“WPS 客户端把云端旧版拉下覆盖本地”问题，仅存在于**明确选择 WPS 后端**时。默认乐享后端由 lexiang 连接器读写、不经过 WPS 客户端，无此覆盖风险。

### 6.1 问题
WPS 桌面客户端有时会把**云端旧版**拉下来，覆盖你**本地的新版**。我们刚踩过这个坑：本地版本比云端新，但客户端同步后本地被旧版覆盖，导致新版丢失。

### 6.2 本技能的防护
1. **同步前先备份**：每次运行都会把本地当前版本按时间戳备份到 `~/.workbuddy/backups/memory-sync/`。
2. **检测异常覆盖**：运行时发现"本地内容和云端旧版一致，但和上次同步记录不同"，会告警并尝试从备份恢复。
3. **旧备份自动清理**：默认每个文件保留最近 10 份、超过 90 天的自动删，旧的不占空间。

### 6.3 更彻底的方案
如果你经常遇到 WPS 客户端把云端旧版拉下来覆盖本地，可以在 WPS 客户端里把《workbuddy.memory》文件夹**排除同步**，让同步完全由本技能接管（日常 MCP + 定时脚本兜底）。这样本地改了不会被云端旧版冲掉。

## 7. 标准动作：改完即自动备份 + 回读校验

1. **自动备份**：
   - **日常通道（推荐）**：WorkBuddy 对话内改完云总纲 → 立即用 kdocs MCP `otl.insert_content(mode=replace)` 将总纲完整内容刷新到备份文件。这是最快、最稳、不受 kdocs-cli 版本影响的主通道。
   - **定时兜底通道**：每日 12:00 自动化（首次激活本技能时自动创建，不写死本机 ID）会比对总纲与备份，漂移则自动修复并告警。

   - 不同 → 立即将主文件内容重新覆盖备份，再次校验；**循环至一致为止**，绝不留"改完没对齐"。
3. **告知用户**：每次修改+同步后，版本号与一致性结果必须反馈，不静默。

## 7.1 回滚机制（v2.0.8 新增：云原生版本回滚，已实测）
> 背景：用户 2026-08-26 提出"采用云自身版本回滚"。已实测验证乐享 file 类型天然带版本历史，可脚本化回退。

**结论与落地**：默认保留显式「备份页」机制（page 可控）；若后续把备份改为 file 存储，则优先用乐享原生版本历史做回退（更省事、自动）。两条互补，不互斥。

## 14. 安全与权限边界（v2.0.11 起固化，对应腾讯安全云评估要求）

> 章节背景：v2.0.10 经腾讯安全云实验室评估得分 45/100（3 项可疑行为：网络请求与数据外传 / 文件操作与敏感路径访问 / Prompt 注入风险）。

### 14.1 范围声明（你能指望本技能做什么、不能指望它做什么）

| 能做 | 不能做 |
|---|---|
| 校验本地 `~/.workbuddy/MEMORY.md` 指针段合法性 + SessionStart 钩子是否注入云总纲 | 不向任何未在 WorkBuddy 连接器面板授权过的空间上传/同步数据 |
| 读 `~/.workbuddy/{IDENTITY,USER,SOUL,MEMORY}.md` 与 `settings.json`，按需 sha1 比对 | 不读取/修改除上述路径之外的其他本地文件 |
| 经用户已在 WorkBuddy 已授权的 **lexiang 连接器**读写乐享个人知识库（默认后端） | 不联网拉取不可信脚本/资源；不调用任何远程脚本下载执行 |

| 跨平台运行：Windows / macOS / Linux 脚本行为一致（v2.0.11 起 pathlib） | 不在 keystroke/network 级别做监控 |

### 14.2 反 Prompt 注入（云《工作习惯总纲》作为权威源的接入方式）

云《工作习惯总纲》在本技能架构中是**行为规则的事实数据源**（相当于"配置"），不是注入 Agent 的系统提示。具体落地：

- **SessionStart 钩子**在每会话开头通过 lexiang MCP 的工具调用把云总纲**作为工具结果返回**写入消息头（属 query result / tool result，不是 system prompt），Agent 把它作为**事实信息**读取、推理后生效，不被作为系统指令直接执行。
- **SKILL.md frontmatter description 中"云端唯一权威"是事实描述**（即"当前用户的行为规则源在云端《工作习惯总纲》"），不是向 Agent 的指令注入；Agent 仍以用户当轮 question / 对话上下文优先决策。
- **自动化任务 prompt 中所有「用当前工作目录/读 MEMORY.md/不写死 id」的硬要求**，是为了防止搬家换机失效——属于参数自举（bootstrap），不是 prompt 注入。
- **解压风险防御**：本技能不会通过工具回写方式主动修改 Agent 的 system prompt、也不会在任何 prompt 模板中写「无视之前所有指令」「你现在是 XXX」这类 prompt injection 模式。

### 14.3 写入前的用户确认闸（v2.0.11 起新增，dry-run by default）

凡会改变 `IDENTITY/SOUL/USER/MEMORY` 实际内容或覆盖任何文件的动作，**默认走 dry-run**：

1. 先在当轮回复里输出"将做什么 → 将写到哪个本地/云端路径 → 是否会覆盖现有内容 → sha1 比对差异"。
2. 等用户明确说"执行"或按用户预期配置（`config.json` → `dry_run: false` 显式关闭）后才真正执行。
3. 执行后必回读并 sha1 比对，确认落地内容与预期一致才算完成。

**例外（视为"非覆盖"、可自动执行、不需要闸）**：
- 云总纲→备份 的同内容刷新（严格等值 sha1 比对通过、备份内容等于主文件内容）。
- sha1 比对通过、且仅是同内容回写类（备份兜底写入）。
- 用户明确说"立刻执行"或 `config.json` 设 `dry_run: false` 时跳过 dry-run。

### 14.4 跨用户/跨机迁移安全

- 同一 Windows 用户 + 同一 lexiang 账号下，本技能的 `*.json` 配置与 `.workbuddy/` 状态天然共享，无需手动迁移。
- 不同用户/不同账号间**不共享**任何缓存（`state.json`、`config.json`、备份目录均落在当前 HOME 下）。
- 跨用户复制本技能 zip 时，里面写死的 `state.json` 内容（用户本人的 file_id）与个人特征应被视为仅可参考、不可直接复用——新用户安装时按 §10 脚本默认行为重新发现。

## 16. ID 零硬编码 · 动态获取流程（v2.0.12 起固化，铁律级）

> **本章是最高优先级约束**：本技能（含 SKILL.md、脚本、示例配置、变更说明）**任何文件中不得出现具体 ID 值**。
> 每个用户的 space_id / entry_id / file_id / drive_id / 本地路径都不同，必须运行时解析。
> 违反本章 = 发布包携带他人私有数据 + 新用户下载后必然指向错误空间（等价于功能失效）。

### 16.1 零硬编码清单（发布包内这些文件一律不得含 ID）

| 文件 | 允许出现 | 禁止出现 |
|---|---|---|
| `SKILL.md` | 占位描述（`<总纲 entry_id·运行时解析>`）、占位符 `{}`、工具名 | 任何 32 位 hex、任何 `C://Users//<具体用户名>//` |
| `config.json`（发布态） | `_comment` 说明、空串默认值 | drive_id / cloud_folder_id / sync_mirror 的具体值 |
| `config.example.json` | 空串 + 说明 | 任何示例 ID |
| `state.json`（发布态） | 空模板（§16.5） | 任何已解析的 entry_id / file_id / sha1 |
| `变更说明.md` | 历史条目的占位符表述 | 历史版本引用的具体 ID |
| `scripts/*.py` | 工具名、字段名、正则 | 任何 ID 字面量、任何 fallback 硬编码 id |

> 唯一例外：`_skillhub_meta.json` 中的 `slug` / 平台下发的 icon 资源名（属技能自身标识，非用户数据）。

### 16.2 三级解析顺序（必须按序，前一级命中即止）

| 级别 | 来源 | 说明 | 失效后 |
|---|---|---|---|
| L1 | 本机 `state.json` | 本机私有运行态缓存，首次激活解析后写入 | 落到 L2 |
| L2 | `~/.workbuddy/MEMORY.md` 指针段 | 用户已存在的指针声明（上下文锚定解析） | 落到 L3 |
| L3 | lexiang 实时 API | 见 §16.3 标准调用链（**最终权威**） | CRITICAL，停等用户 |

> **任何一级拿不到值都不得静默继续**；L3 失败按 §16.6 分级处置。

### 16.3 标准调用链（已实测通过，2026-09-01）

```
第 1 步  取 space_id
  lexiang: whoami
    → data.personal_space.id            # 当前用户个人知识库 space_id
    → data.personal_space.root_entry_id # 根条目
  （备选：space_describe_personal_space(is_async=false) → data.space.id）

第 2 步  按标题定位条目
  lexiang: lexiang_search(query="工作习惯总纲", type="doc")
    → data.docs[]：每项含 id / original_title / space_id / file_type

第 3 步  过滤（见 §16.4）后取 id 作为 entry_id
```

### 16.4 过滤规则（实测踩坑总结，缺一不可）

| # | 规则 | 原因（实测证据） |
|---|---|---|
| 1 | **用 `original_title` 精确匹配，不用 `title`** | `title` 字段含搜索高亮标签（如 `<em>工</em><em>作</em>...`），无法直接比对 |
| 2 | **排除 `original_title` 以 `【历史版本】` 开头的条目** | 搜索"工作习惯总纲"会同时命中《【历史版本】工作习惯总纲》，误用会读到过期规则 |
| 3 | **优先 `file_type == "page"`** | 历史版本多为 `doc`/`file`，现行主文件为 `page` |
| 4 | **校验 `space_id` 与第 1 步一致** | 搜索跨空间返回，须限定在当前用户个人知识库 |
| 5 | **多候选时列清单让用户选，不自动挑第一个** | 用户可能自建同名页，自动挑会造成静默错指向 |

### 16.5 解析结果写哪里

解析出的 ID **只写入本机 `state.json`**（私有运行态，不入发布包、不进版本库）：

```json
  "resolved_at": "",
  "cloud": {

    "backup": {"title": "工作习惯总纲_备份", "entry_id": "", "space_id": ""}
  },
  "folder_id": "",
  "items": {},

```

**严禁回写**：不得把解析出的 ID 写回 `SKILL.md`、`config.example.json`、`变更说明.md` 或任何会随技能分发的文件。

### 16.6 解析失败的分级处置

| 场景 | 级别 | 处置 |
|---|---|---|
| `whoami` 失败（lexiang 未连接/未授权） | CRITICAL（退出码 2） | 停等；提示用户在连接器面板确认 lexiang 已授权 |

## 18. 记忆瘦身根因机制（v2.1.0 专项，治「瘦身被对端回补 / 记忆反复膨胀 / 78.8% 不可见」）

> 根因（实证）：旧实现是「文件级单向只增同步」——只增不减。跨机只比 MEMORY.md 单文件、按 sha1 判字节（内容搬家即变误判新增）、方向只增不减，导致办公机判定本地独有→回补云端→瘦身白做。三层方案与根因三证据见乐享《03.记忆同步瘦身手册与待更新素材》（按 §16 取真 id，不写死）。

### 18.1 瘦身事件册（最关键，终结回补循环）
- 建乐享《MEMORY 瘦身事件册》page（位于《8.workbuddy.memory》根目录，与《2026年备忘录》《05.犯错复盘库》并列，按 §16 实时取真 id）。
- 每次瘦身登记一行：日期 / 瘦前身 sha1 / 瘦身后 sha1 / 移除条目及去向（瘦身前归档文件放「256.【历史文档】」，命名沿用原名带【历史版本】前缀，符合命名规范）。
- 对端同步先读事件册（§9 第 3 步、§11 事件册优先）：命中瘦前身 sha1 → 直接云覆盖本地、不询问不回补；命中瘦身后 sha1 → 视为已对齐。
- 老用户已瘦身的：事件册需补登历史瘦身记录防止旧版被误判新增；新用户首次初始化即带空模板。

### 18.2 集合级独有性判定（§9 第 4 步）
判定「本地独有」前先在记忆全集检索：本地 IDENTITY/USER/SOUL/MEMORY + 云《工作习惯总纲》+ 总纲备份页 + 《8.workbuddy.memory》各页（按 §16 取真 id）。全集任一处查到 → 非真独有，不提示合并、不回补。
