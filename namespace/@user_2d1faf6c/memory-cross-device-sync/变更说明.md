## v2.0.12（2026-09-01，ID 零硬编码专项 · 全包无具体 ID）

### 优化目标

根治「技能包内写死作者本人 ID」这一结构性问题。此前版本虽在 §0.4 / §4 做了局部脱敏，但全包仍有 5 处残留（SKILL.md §1.1 备份条款的 entry_id、变更说明历史条目的两个 entry_id、config.json 的作者 drive_id / 云文件夹 id / WPS 同步盘路径、state.json 的作者本机 file_id 与 sha1、_skillhub_meta.json 的打包机用户名路径）。这些残留对新用户意味着两件事：**私有数据随包分发** + **下载后指向错误空间（功能必然失效）**。本版做到「包内零 ID、ID 全靠运行时获取」。

### 主要变更

#### 1. 新增 §16「ID 零硬编码 · 动态获取流程」（核心）

- **16.1 零硬编码清单**：逐文件列出「允许出现 / 禁止出现」，唯一例外是 `_skillhub_meta.json` 的技能自身标识。
- **16.2 三级解析顺序**：L1 本机 `state.json` 缓存 → L2 `~/.workbuddy/MEMORY.md` 指针段 → L3 lexiang 实时 API（最终权威）；任一级拿不到值不得静默继续。
- **16.3 标准调用链（已实测）**：`whoami` → `data.personal_space.id` 取 space_id；`lexiang_search(query="工作习惯总纲", type="doc")` → `data.docs[]` 取 id / original_title / space_id / file_type。
- **16.4 过滤规则（实测踩坑，缺一不可）**：
  1. 用 `original_title` 精确匹配，**不能用 `title`**（后者含搜索高亮标签 `<em>…</em>`，无法比对）；
  2. 排除以 `【历史版本】` 开头的条目（搜索会同时命中过期版本，误用即读到过期规则）；
  3. 优先 `file_type == "page"`（历史版本多为 doc/file，现行主文件为 page）；
  4. 校验 `space_id` 与第 1 步一致（搜索跨空间返回）；
  5. 多候选时列清单让用户选，不自动挑第一个（防静默错指向）。
- **16.5 解析结果只写本机 `state.json`**，严禁回写 SKILL.md / config.example.json / 变更说明.md 等分发文件。
- **16.6 解析失败分级处置**：whoami 失败 / 命中 0 条 = CRITICAL(2)；多同名候选 / 只命中历史版本 = WARN(1)；成功 = INFO(0)。
- **16.7 发布前自检 `--audit-ids`**：扫描 32 位 hex、用户名绝对路径、疑似 WPS ID，有命中即退出码 2，禁止打包。

#### 2. 全包残留清理（5 处）

- SKILL.md §1.1 备份条款：`（乐享 entry_id d945db3f…）` → `（乐享 entry_id **实时解析**，按 §16 用 whoami → lexiang_search 取当前用户真实值，正文与脚本均不写死）`。
- 变更说明.md 历史条目：`总纲/备份 id 全部改为乐享 entry_id（fb37f0b1… / d945db3f…）` → 改为占位符表述；v2.0.11 条目内引用的两个具体 id 同步替换为 `<总纲 entry_id·运行时解析>` / `<备份 entry_id·运行时解析>`。
- config.json：`drive_id` / `cloud_folder_id` / `sync_mirror` / `parent_id` 全部清零，并加 `_comment` 说明「ID 型字段一律留空，由每个用户首次激活时按 §16 动态解析」。
- state.json：从「作者本机私有 file_id + sha1」改为**空模板**（含 `_comment` / `_version` / 空的 `cloud.master` / `cloud.backup` 结构）；另新增 `state.example.json` 作为模板参考。
- _skillhub_meta.json：删除 `iconLocalPath` / `iconDownloadedFrom` 的打包机用户名路径，`iconSource` 留空由平台下发。

#### 3. sync_backup.py 新增两个子命令

- `--discover`：ID 动态解析。L1/L2 命中判断 + L3 待执行 MCP 调用清单输出。脚本层不假装能调 API——L3 明确交给 Agent 经 lexiang MCP 执行（诚实边界）。
- `--audit-ids`：发布前自检，扫描 8 个分发文件，三类违规（32 位 hex / 用户名绝对路径 / 疑似 WPS ID），有命中退出码 2。

#### 4. 元数据

- `_meta.json` / `_skillhub_meta.json` / SKILL.md frontmatter 版本同步升 2.0.12；frontmatter description 追加 v2.0.12 段（保留全部历史措辞）。
- 新增 §17「与 v2.0.11 的差异速查」表。

### 实测验证（2026-09-01，本机）

- `whoami` → space_id 解析成功；`lexiang_search(query="工作习惯总纲", type="doc")` → 命中 20 条，其中现行主文件 `file_type=page`、`original_title="工作习惯总纲"`，同时存在 `【历史版本】工作习惯总纲`（file_type=doc）干扰项——**证实 §16.4 第 2、3 条过滤规则必需**。
- `--discover` 的 L2 解析结果与 L3 实测 API 结果**完全一致**（交叉验证通过）。
- `--audit-ids` 扫描 8 个文件，零违规，退出码 0。

### 影响范围

- **新用户**：下载即零配置可跑，首次激活按 §16 解析自己的空间，不再指向作者空间。
- **老用户（v2.0.11 及更早）**：无破坏性变化；唯一可感知差异是 config.json / state.json 被重置为模板，首次运行会重新解析（原私有值不随包分发，属预期）。

### 优化目标

### 主要变更

#### 1. 脚本（memory_sync.py）根因修复
- **删除 `discover_skill_items()` 自动扫描逻辑**：原逻辑会扫描 `~/.workbuddy/skills/` 下每个 skill 的 `SKILL.md` 并塞进同步清单，这是那批 `skills_*.md` 进记忆云文件夹的直接来源；相关两处调用一并清除。

#### 3. 同步清单调整
- 移除"自动纳入用户自建技能配置"这一项，改为明确"排除技能"，并在文档同步范围中明确只同步 `MEMORY.md`（及可选身份文件）。

### 影响范围

- 技能与记忆彻底隔离：技能归 7.workbuddy.skill，记忆归 8.workbuddy.memory，不再串门。
