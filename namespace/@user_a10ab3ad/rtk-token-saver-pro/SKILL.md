### 基础问题
- **Q1: 处理速度如何？** → 单文件 1 秒内，10 个文件以内 5 秒内，大目录（100+ 文件）约 30 秒

### 进阶问题
- **Q4: 如何调整压缩率？** → 使用 `--strategy` 参数：`conservative`（保守）/ `standard`（标准）/ `aggressive`（激进）
- **Q5: 如何输出为 JSON？** → 使用 `--format json` 参数，输出结构化 JSON 便于程序处理
- **Q6: 如何排除某些文件？** → 使用 `--exclude` 参数，支持通配符，如 `--exclude "*.test.rs"`
- **Q7: 压缩后如何验证质量？** → 对比压缩前后的关键信息保留率，检查函数签名/类定义是否完整
- **Q8: 如何保留特定关键词？** → 使用 `--keep` 参数，支持正则表达式，如 `--keep "TODO|FIXME|NOTE"`
- **Q9: 如何处理超大文件？** → 自动启用分块压缩，每块 50K token，合并结果。可用 `--chunk-size` 调整

### 常见坑（避坑指南）
- **坑1：压缩代码文件时丢失函数体** → 激进策略下可能只保留函数签名。如需保留函数体，请使用标准策略
- **坑2：URL 内容抓取不完整** → 部分网站有反爬机制。建议直接粘贴文本内容
- **坑3：中文文档压缩后语义偏差** → 中文压缩比英文更难保持语义。建议使用保守策略，并人工复核
- **坑4：批量处理时个别文件失败** → 不会中断整个流程，失败文件会在报告中单独列出
- **坑5：JSON 输出格式不符合预期** → 检查是否使用了 `--format json`，且输入内容是否为文本类
- **坑6：压缩后代码无法通过编译** → 压缩可能删除了必要的语法结构（如分号、括号）。代码文件建议使用保守策略
- **坑7：对话压缩后丢失关键决策** → 对话压缩默认保留决策点和待办，但若对话过于冗长，可能遗漏。建议压缩前明确指定"重点保留什么"
