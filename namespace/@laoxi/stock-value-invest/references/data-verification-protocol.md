# 数据校验协议（多信源 / 信源分级 / 红线）

> 承接 SKILL.md 前置 2、前置 3 的「铁律」细则。每一条违反即校验未通过，报告不得发布。

---

## 一、信源六级体系

| 等级 | 含义 | 示例 |
|---|---|---|
| 🟢🟢🟢🟢 T0 | API 直取 | yfinance / AkShare / 交易所 API |
| 🟢🟢🟢 T1 | 一级官方 | 公司年报/季报、交易所公告、监管披露 |
| 🟢🟢 T2 | 二级权威 | 彭博/路透/财新、券商深度研报、专业数据库 |
| 🟢 T3 | 三级参考 | 垂直媒体、行业协会 |
| 🟡 T4 | 单源/弱源 | 单一媒体、互相抄录 |
| 🔴 T5 | 传闻 | 社交平台未经证实 |

**铁律**：每个定量数据必须行内/相邻列标等级，且至少 1 个 T2 以上；报告末尾 **K.4** 必须列所有 🟡/🔴。

---

## 二、价格类数据三源硬线

1. 现价 / 市值 ≥ 3 个独立权威源交叉验证（1 个 API + 1–2 个网页源即满足）。
2. 每个价格必标 `[数据类型 / 取数时间戳 / 币种]`。
3. 取数后检查 `meta.engines_used` / `errors`；双引擎失败 → 首页 ⚠️"数据降级"。

---

## 三、头号红线：数据类型混淆

严禁以下混淆（血泪教训：曾把研报目标价当现价，结论全反）：
- 研报目标价 ≠ 现价
- 52 周区间 ≠ 现价
- 分析师一致预期 ≠ 实际业绩
- DCF 估值 ≠ 市场现价

**护栏**：任何进入评分的"价格"必须能追到 T0/T1 实时源；否则降级并在 K.4 披露。

---

## 四、跨市场分别独立取数

- AH/ADR 标的必须**分别独立调用**取数脚本，禁止汇率换算后混用。
- AH 溢价方向须从原始价格（人民币/港币各自）重算，不得套用单一汇率。
- 美股 ADR 与普通股数量、汇率须在报告中显式标注。

## 六、降级策略（脚本缺失/网络受限）

- 优先用用户上传的财报/数据 → 标 T1。
- 其次联网搜索官方披露 → 标 T2/T3。
- 再次网页行情 → 标 T3/T4，须在 K.4 披露为弱源。
- 无任何可核验源 → 首页 ⚠️"数据降级"，量化结论降权，定性结论显式说明"数据不足"。
