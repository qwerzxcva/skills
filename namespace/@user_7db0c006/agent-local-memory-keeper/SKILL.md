# AI Agent 记忆系统

> **一句话**：给 AI 的跨会话长期记忆——你说「记一下…」「找一下之前那个…」，AI 自动存、换说法也能召回、自动去重纠错分层。**装完即用，全程对话操作，不用读配置、不用记命令**，纯本地零云端。

## 🪟 关于弹窗：那不是报错，是钩子在工作（先读这一条）

> 使用中你可能会看到界面**偶尔闪一下「执行中」提示条**——**这不是 BUG、不是报错，更不代表记忆出问题**。

**它到底是什么？**
本 skill 依赖 WorkBuddy 的「钩子（Hook）」机制在后台工作：当会话开始、你每发一条消息、某个工具执行完、会话结束等事件发生时，WorkBuddy 会自动运行本 skill 挂载的钩子脚本，替你完成「自动记下经验 / 召回相关记忆 / 捕获报错 / 会话结束整理」这些动作。

**为什么界面会闪一下？**
当这些钩子脚本被触发运行时，WorkBuddy 会在界面上短暂显示一个**「执行中」状态指示**——这是平台用来告诉你「此刻有一个后台任务正在执行」的 UI 反馈，属于**平台固有行为**，与记忆系统是否出错**完全无关**。

**什么时候会闪、闪多久？**
- 仅 `full` 模式下，钩子每轮对话都会触发，提示条因此可能**每次发送、每次开场都闪一下**；
- `silent` 模式（**默认**）下钩子静默执行，**不再显示**提示条，功能不受任何影响。

**嫌它闪怎么办？**
对 AI 说**「关掉弹窗」**即切到 `silent`；想恢复「每轮自动浮现相关记忆」就说「恢复完整钩子」。**改完重启 WorkBuddy 生效。**

> 一句话：**那个提示条是「记忆系统正在工作」的指示灯，不是故障报警。** 详见下方「🔧 配置指引 · 钩子模式」。

## 🔴 先读 3 条（动手前扫一眼，不读可能丢数据）

> 1. **清理用 `archive`，别拿 `delete --yes` 当常规清理**：`delete --yes` 是真删、不可找回；`archive` 软归档沉底，`recall --deep` 仍可找回。不确定先 `--dry-run`。
> 2. **别把对话原文灌进记忆**：只记**提炼后的结论**（坑 / 纠正 / 最佳实践），当录音笔用会让召回质量塌方。
> 3. **更新完，记得对 AI 说「帮我一键配好」**：钩子 / 守护进程等部署物**不随技能更新自动刷新**，不重跑会一直用旧版。

## 💬 场景对话实操（主轴 2 · 6 大类，每类都有演示）

> 格式统一：**👤 你说什么 → 🤖 AI 做什么**。所有能力都能说人话触发，AI 回显「已记 / 已找到」确认生效。

### ① 记（存经验）
```
👤「记一下：DuckDB 同一文件两个进程同时开会锁住」
🤖 写入经验 + 自动去重 + 自动分类，回显「已记 1 条」
👤「这条结论被新方案取代了」
🤖 把旧结论标为「已取代」，不删除、可回溯
```
> 就这么简单。想一次记多条、纠正旧结论、放行自动暂存——直接说人话，AI 知道该调什么。

### ② 找（召回）
```
👤「找一下之前关于 DuckDB 锁的记忆」
🤖 按语义召回，回显命中条目；可能问「这条有用吗」，回「有用 / 没用」
👤「这条经验在 2026-08 那会儿还有效吗」
🤖 按时间点回溯查询，照「何时生效、何时失效」判定
```
> 想查「某条为什么被召回」也可以直接问 AI，它会拆给你看评分和来源。

### ③ 整理（去重/归档/蒸馏）
```
👤「帮我整理今天记的」
🤖 自动去重 / 纠错 / 归档（永不删），回显「去重 N / 纠错 M / 归档 P」
👤「把相似的记忆归归类」
🤖 聚类返回候选组，逐组问你要不要合并（只标不删）
```
> 「整理」永远只归档不删；真要删，AI 会先把影响面摆给你看、确认后才动手。

### ④ 配置（开关/钩子/IMA/LLM）
```
👤「关掉弹窗」
🤖 切到静默模式，回显「已切静默，重启 WorkBuddy 生效」
👤「配 IMA 知识库同步」
🤖 配置 IMA 知识库，推送前强制脱敏
```
> 所有配置都能说人话完成，不用记命令；改完钩子模式记得重启 WorkBuddy 生效。

### ⑤ 排错（有问题？AI 能定位 + 解决）

> AI 不是只会「转告一句」，而是能**跑体检读真实状态 → 定位根因 → 给解法 → 确认生效**。最常见的 6 类问题，每条都给了「症状 → AI 怎么查 → 怎么解决」：

| 症状 | AI 怎么查 | 怎么解决 |
|---|---|---|
| 记不进去 / 报错 | 跑体检读真实错误码（含修复步骤） | 按步骤修；多数说「帮我一键配好」即可 |
| 找不到 / 结果差 | 跑体检看「语义后端是否降级」 | 降级了 → 说「帮我一键配好」自愈模型缓存 |
| 中文换说法搜不到 | 同上，看语义后端状态 | 修语义模型；离线可先降级词法 |
| AI 反复「再确认」 | 识别为自反馈死循环 | 说「不用校准 / 不用注入」切断 |
| 界面闪提示条 | 识别为钩子指示灯（**非 BUG**） | 说「关掉弹窗」切静默 |
| 记忆凭空少了 | 查变更日志定位是归档还是删除 | 归档可找回；删除不可逆 |

```
👤「为什么找不到我之前记的？」
🤖 跑体检 → 读到「语义后端已降级」→ 回显：「⚠️ 语义模型降级了，这就是找不到的根因；说『帮我一键配好』我替你修」→ 修复后复检回显「已恢复，召回率回 ~90%」
```

> 🩺 **降级不再静默**：召回会带「是否降级」标记、搜不到时附修复提示、注入时降级显式追加「⚠️ 请转告用户」——「降级了却没人知道」已堵死。完整排错 30 题 → `references/QA.md`。

## 🔧 配置指引（哪些要配、怎么配、对 AI 说什么）

**一句话**：对 AI 说即可，AI 背后跑 `keeper_setup.py`，不用手敲环境变量。你可能手设的只有一个：`AI_MEMORY_STORE`（记忆库根目录；回退链 `AI_MEMORY_STORE` → `~/.keeper/store_root` → 平台默认）。

### 钩子模式（弹窗开关，见顶部「🪟 弹窗不是 BUG」）

| 模式 | 弹窗 | 自动加载记忆 | 适合谁 |
|---|---|---|---|
| `full` | 有（每轮/开场闪一下，是钩子指示灯，非 BUG） | ✅ 每轮自动浮现 | 不介意闪条、要「保证浮现」 |
| `silent`（**默认**） | **无** | 改由 AI 按需 recall | **大多数用户** |
| `off` | 无 | 无 | 想完全手动 |

切换：说「关掉弹窗」（→ silent）/「恢复完整钩子」（→ full）。**改完重启 WorkBuddy 生效**。

### 常用开关（口语可切）

| 开关 | 默认 | 对 AI 说 |
|---|---|---|
| 后台自动记忆 `auto_capture` | ✅ 开（每 20 轮沉淀） | 「先别自动记」/「改成每 50 轮」 |
| 上下文自动注入 `inject_enabled` | ⛔ 关（省 token） | 「开启自动注入」 |
| 置信度校准 `feedback` | ✅ 开（每会话 3 次） | 「不用校准」 |
| 每日自动整理 | ⛔ 关 | 「建一个每天自动整理的定时任务」 |

> 仅 2 项需手动开（外部/重资源）：**IMA 云端同步**（说「配 IMA 知识库同步」）、**本地 LLM/Ollama**（~5GB）。其余运行时开关收口在 `store/config.json` 的 `keeper` 块（与代码 `KEEPER_DEFAULTS` 一一对应，优先级 **env > `store/config.json` > 默认值**）：

```json
{
  "keeper": {
    "embed_backend": "fastembed",
    "embed_online_url": "",
    "inject_enabled": false,
    "inject_daily_cap": 6,
```

## 🔴 红线与边界（唯一真源）

> 🔴 红线分两组：**数据类**（不可逆/会丢会泄）与**质量类**（数据还在，但你被误导）——两组都不可破，无论你怎么说 AI 都守。

**A · 数据类红线**
- **A1. 绝不批量硬删**：`reflect`/`archive`/`decay` 只做去重·纠错·归档（软保留，`recall --deep` 可找回）；唯一真删是显式 `delete --yes`，单次单条。
- **A2. 删必须显式 `--yes`**：不带 `--yes` 的删除一律被拒、文件原样保留。
- **A3. IMA 明文库强制脱敏**：推送前自动 strip 凭证/真实路径/邮箱，脱敏后复检；任何残留直接失败退出，绝不交付明文。

**B · 质量类红线**
- **B1. 静默质量退化必须显式可见**：语义后端失败会退回词法（召回 ~90%→~30%）。`recall --with-meta` 返回 `meta.fell_back_to_lexical`，空结果附 `empty_hint`（含修复命令），注入时降级在上下文显式追加「⚠️ 请转告用户」提示——**绝不允许「降级了但没人知道」**。
- **B2. 重要记忆分类强制**：`importance ≥ 0.7` 且低置信自动分类时，标 `classify_review` 并告警，不静默猜分。

**边界（设计使然，非缺陷）**
- 环境级故障（Python 缺失/模型下载失败）→ 需你补环境。
- **清理类命令怎么选**：`purge` **不是**通用清理——只真删「已归档/已被取代」且超龄(180天)+低重要度(<0.4)的软删件，`active` 条目（含今天刚记的）永不在候选内。清「今天的」用 `reflect --auto` 或 `archive`。
- **域分类落空 = `domain=None`，是设计不是缺陷**：未命中域 → 存 `domain=None`（非丢失）；想自动落域显式设 `KEEPER_DOMAIN_FALLBACK=<域>`（默认关）。

**防 AI 反复确认死循环**：`feedback` 每会话 3 次 + `inject` 每会话 6 次双闸门；说「不用校准/不用注入」即切断。

## 常见问题（精简 6 条，其余见 `references/QA.md`）

- **误删了能恢复吗？** 能。查这条的历史版本一键回滚，或用备份包整库恢复；删除前优先归档（可找回）。
- **「整理」会删记忆吗？** 不会。只去重/纠错/晋升/归档，绝不删除；「遗忘」只是降权 + 归档，随时可找回。
- **中文换说法搜不到？** 多半是语义模型降级了——对 AI 说「看看语义后端状态」，若显示降级，说「帮我一键配好」即可修。
- **需要联网吗？** 默认纯本地零云端；仅首次装语义模型 / 可选本地大模型需联网一次。
- **记忆存在哪/怎么备份？** 默认在本地用户目录（Windows `~/AI记忆`、mac/Linux `~/.ai-memory`）；说「备份一下」导出压缩包，「恢复一下」还原；跨电脑合并迁移说「搬到另一台电脑」。
- **AI 反复"再确认"死循环？** 说「不用校准/不用注入」，或让 AI 关掉这个开关。
