# Keeper 能力开启三桶分类

> 📌 **功能变更以根目录 `CHANGELOG.md` 为唯一权威源**。

本文件把 keeper 全部能力按「是否需要你动作」分成三桶，对应 `SKILL.md`「🔧 配置指引」。目的：消除「那么多功能没开」的错觉——绝大多数能力其实已默认开，少数因安全 / 资源 / 外部依赖必须手动。

## ✅ 桶 1 · 无要求，默认已开（随周维护自动跑，零操作）

这些能力**没有 on/off 开关配置项**，首次配置时「周维护」自动化已自动挂上并每周运行，即视为已启用。想手动跑一次也对 AI 说对应命令。

| 能力 | 默认状态 | 手动触发（对话） |
|---|---|---|
| 中文语义召回 (fastembed) | ✅ 开箱默认 | — |
| 钩子 silent（无弹窗自动记忆） | ✅ 开箱默认 | 「关掉弹窗」→ silent / 「恢复完整」→ full |
| converse 自动沉淀 (20 轮) | ✅ 开箱默认 | 「改成每 50 轮」/「先别自动记」 |
| 分类 / 分层 / 反馈校准 | ✅ 开箱默认 | — |
| 矛盾检测（扫描） | ✅ 随周维护跑 | 「跑一次矛盾检测」 |
| decay 沉底 | ✅ 随周维护跑 | 「把太久没用的降权」→ `decay --apply` |
| 聚类 / 主题标签 | ✅ 随周维护跑 | 「跑一次聚类」→ `cluster --apply` |
| reflect 整理 | ✅ 随周维护跑 | 「帮我整理今天的记忆」 |
| ANN 加速 | ✅ 库 ≥50 条自动 | — |
| WorkBuddy 原生记忆自动沉淀（会话结束） | ✅ 开箱默认（会话结束自动） | 会话结束自动把 WorkBuddy 原生记忆（L2 + 工作区 .workbuddy/memory）沉淀进 keeper——只读 WB、只写 keeper、规则模式、幂等不重复；手动触发仍可用 `harvest --self-learn --with-workbuddy` |

> ⚠️ 注意：decay / 聚类 / reflect / 矛盾扫描是**周期性维护动作**（非破坏性，`--deep` 可找回），不是「开关」——挂上週维护即启用。

## 🔧 桶 2 · 需开但无配置要求（一句话触发，单独说明）

这些保持 opt-in，但开启只需一句话、无需配任何东西。详细原理见 `references/FEATURES.md`。

| 功能 | 为什么归这桶 | 怎么开（对话） |
|---|---|---|
| 矛盾自动修复 `--fix` | 命令简单，但**真生效需 LLM**；离线只能扫、不能判重 | 先开 LLM（线上/本地），再「跑一次矛盾修复」 |
| Dashboard 可视化 / 元记忆 about_axis | 已可用，进阶用法 | 「生成可视化 Dashboard」 |

## 🔒 桶 3 · 需手动开 + 有配置要求（清单）

这些**故意不加默认开**——要么有不可逆风险、要么依赖外部服务、要么吃重资源。

| 功能 | 配置要求 | 前置 / 风险 | 怎么开 |
|---|---|---|---|
| IMA 云端同步 | 连 IMA MCP + 配知识库 id | 外部依赖；推送前强制脱敏 | 「配 IMA 知识库同步」 |
| Ollama 本地 LLM | 装 ~5GB 模型 | 吃内存/GPU，低配卡死 | 见 `references/FEATURES.md` |

> 这桶就是 SKILL.md 标注的「2 项需手动开启」（IMA / Ollama）。它们必须留在手动——硬默认开会危害用户（5GB 下载 / 记忆上云）。
