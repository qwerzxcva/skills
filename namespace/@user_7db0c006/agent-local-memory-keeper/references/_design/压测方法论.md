## 0. 铁律

**压测结论可信的唯一前提：被测代码真的跑了，且数据真的进了被测路径。**

先看这一条，再信任何数字。连「实跑取证」都会骗人——前提是测试本身走了正确的路径。

---

## 1. 四面红旗（都曾让我们翻车）

### 红旗 1 — 数据半残（绕过真实 API）

- **错法**：直接 `INSERT` 进 SQLite，绕过 `deposit()`。
- **后果**：`memories/*.json` 文件库为 0 文件 → recall 的 `_all_mems()` 读 0 条 → 所有 recall/cache/maintenance 指标在**空集**上测。
- **陷阱**：`reembed=0` 在空集上是「没东西可重嵌」的真值，不是「复用正常」的证据。
- **正解**：压测必须走真实 `deposit()`（或等价地：真实写 `memories/{mid}.json` + `_emb_store_put_many`），确保 recall 读得到数据，再信任何 recall 指标。

### 红旗 2 — 向量格式错

- **错法**：vec 存成 raw `BLOB bytes`（`sqlite3.Binary(tobytes())`）。
- **后果**：`_emb_store_load_all`（memory_ops:2434）用 `json.loads(r[1])` 读 → 解析失败，**整表作废**。
- **正解**：vec 按真实格式存 **JSON 字符串**（`json.dumps(vec)`）。落库前对照 `_emb_store_load_all` 的读取方式，格式必须一致。

### 红旗 3 — 缓存假象（embed_batch 杠杆）

- **错法**：batch 喂「刚 deposit 过的同组文本 + 开着 RAM 缓存」→ 100% 命中缓存 → 算出 **550×**。
- **正解**：杠杆必须「**全新文本 + `use_cache=False`**」测，真实杠杆仅 **~1.4–1.66×**（不值得为此重构 deposit 路径）。

### 红旗 4 — 进程内缓存污染（warm2 不可信）

- **错法**：warm1 / warm2 在**同进程**测；recall 的 `_MEM_CACHE`（memory_ops:3118，进程级）让 warm2 命中 warm1 已读入内存的全量 mem。
- **后果**：同规模 warm2 读数失真（`1k0 warm2=2.92s` vs `1k1 warm2=0.516s`，差 **5.6×**），不能再当作「稳定成本」。
- **正解**：第二次查询必须**独立子进程**测（模拟真实 CLI 重调用，`_MEM_CACHE` 不跨进程）。harness 已用 `--recall-once` 模式实现。

## 2. 可信压测运行规范

| 项 | 规矩 |
|---|---|
| 隔离 | 用 `--root` 指向临时目录（如 `_bench_root_{scale}`），**绝不碰真实库** `本地记忆库` |
| 不污染 | 全程 `KEEPER_EMBED_DISK_CACHE=0`，避免写入真实查询缓存 |
| 验证落地 | 跑完先查 `memories/*.json` 文件数 == 预期条数，再信任何 recall 指标 |
| 杠杆测法 | `measure_batch_leverage` 用全新文本 + `use_cache=False` |
| 稳定成本 | recall 第二次查询走独立进程（`--recall-once` 模式） |
| 重嵌计数 | 用 `_emb.embed` 探针（`expand_synonyms` 不调 embed，计数精确 = query 1 + 重嵌条数） |

---

## 3. 当前已验证的真实结论（v2，2026-08-05）

- 真实库 **28 条** recall ~0.5s，**完全够用，无需优化**（YAGNI）。
- embed_batch 真实杠杆 **~1.5×**，不重构 deposit。
- 冷召回（warm1，独立进程）纯 I/O+余弦：1k ≈ 7.4s，1w ≈ 197.6s；**1w 瓶颈在 SQLite 向量全量加载 + 余弦**，非纯文件 I/O（超线性）。
- **1k1（10% 旧格式混入）reembed=100（仅那 10%），首次 recall 后自愈，无全量爆炸** —— `_emb_store_refresh_backend` 的「按 model 字段不一致逐条重嵌」逻辑验证通过 ✅。

## 4. 运行方式

```bash
# 概念命令：bench_harness.py 为方法论中的示意脚本（未随 skill 分发，实际以自写探针为准）
python <探针>.py 1000 0        # 1000 条，0% 旧格式
python <探针>.py 10000 0.1     # 1w 条，10% 旧格式（验证自愈）
python <探针>.py --recall-once <root> <query>   # 独立进程单次 recall（warm2 用）
```

> 注：harness 位于压测工作区 `<探针脚本>`，非 skill 运行时代码；本笔记随 skill 分发，运行时按需调用。
