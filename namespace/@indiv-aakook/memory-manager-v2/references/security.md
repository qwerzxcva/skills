## 一、威胁模型与信任边界

| 主体 | 信任级别 | 说明 |
|------|:--------:|------|
| 记忆文件内容（`.workbuddy/memory/**/*.md`） | **不可信数据** | 由多次会话累积，可能含从网页/邮件/文档复制的任意文本 |
| 导入的 ZIP / 备份清单 / 快照内容 | **不可信输入** | 可能来自他人机器、下载渠道或被篡改 |
| 本技能源码 | 可信 | 无网络外发、无动态执行、无子进程 |
| 宿主工作区路径参数 | 半可信 | 经 `resolve()` 规范化，越界即拒绝 |

**核心承诺**：记忆内容**始终被当作数据**，绝不被解释为指令。本技能只做计数、排序、
截断、复制、删除 —— 不执行、不评估、不外发记忆内容。

> 把记忆内容当成指令来执行，属于**宿主 Agent 的责任边界**，不属于本技能。
> 本技能是本地文件工具，**不做注入拦截、不做内容脱敏、不做导出加密**。

## 三、ZIP Slip 防御（`io.py::_import_safe_target`）

**4 道拒绝规则 + 1 步路径归一化**，按顺序执行、缺一不可：

1. **穿越分量拒绝** —— 任一分量为 `..` 或空即拒。
   *V4.0.2 修复*：此前对**首段**放行（`and i > 0`），于是 `../x.md` 被判为「无穿越」——
   把「拒绝」降级成了「碰巧被工作区边界兜住」。
2. **绝对路径拒绝** —— `/x`、`\x`、`C:x` 一律拒绝。
3. **路径归一化** —— `\` 统一转 `/`，剥离前导斜杠。
4. **扩展名白名单** —— 只允许 `.md` 与 `.summary`。
5. **resolve 后边界校验** —— 解析路径必须落在工作区内（防符号链接逃逸）。

## 四、ZIP Bomb 与导入配额

| 限制 | 阈值 | 超限行为 |
|------|:----:|----------|
| 单文件解压后体积 | 1 MB | 记入 `errors` **且跳过写入** |
| 条目总数 | 1000 | 整包拒绝 |
| 解压总大小 | 50 MB | 整包拒绝；写入过程分块追踪，中途超限即中断并删除半成品 |

**V4.0.2 修复**：单文件超限此前**只记 errors 不跳过** —— 20MB 文件照样落盘，
而读取侧 1MB 上限又让它永远读不出来（`analyze` 报 0 文件，只有 `doctor` 报「异常大文件」）。
等于往记忆目录里塞了一颗哑弹：占空间、看不见、清不掉。

## 五、删除、回滚与完整性

- **先快照再动刀（6 处）**：`govern` / `compact` / `clean` / `cache-clean` / `dedup` / `archive`
  落盘前自动建快照，存于 `<workspace>/.workbuddy/memory_snapshots/`，最多保留 5 个。
  该目录位于 `.workbuddy/memory/` **之外**，不进上下文、不占 token。
  *V4.0.2 起补齐* —— 此前只有 `govern` / `compact` 有快照前置。
- **回滚只覆盖同名文件**，绝不因回滚删文件。
- **归档而非删除**：`auto-clean` / `archive` 先压缩成 `.md.gz` 再移除原文件。
- **受保护目录**：`memory/` 不受 `clean` 影响；`MEMORY.md` 不被自动清理。
- **备份完整性（V4.0.2 修复）**：备份清单记录每文件哈希，还原时**逐文件校验**；
  不一致即跳过并计入 `skipped`。此前清单存了哈希却**从不读取**，是「假完整性」。
- **清单不可信**：还原前校验清单 key 的边界 —— 穿越分量 / 绝对路径 / 解析越界一律拒绝。

### 完整性清单 SHA256SUMS（V4.0.3 新增）

快照与备份产物在落盘时**同时写一份 `SHA256SUMS`**，可用系统自带工具的
`sha256sum -c` 直接交叉验证（GNU coreutils 的 `<hash>  <relpath>` 格式）：

- **全量哈希**，不是 `token.compute_content_hash` 那种只读前 50KB 的近似 ——
  后者对 50KB 之后的改动完全不敏感，拿它做清单等于「假完整性」。
- **校验入口**：`snapshot --verify [--name N]` / `backup --verify`，均为只读。
- `verify` 判通过的条件是「哈希全对 **且** 无缺失 **且** 无清单外新增文件」——
  只报告不判定，会让「多出来的文件」永远没人看。
- 清单缺失时返回 `ok=false`，**不**返回「无从校验故放过」。
- 受测行为见 `tests/test_hardening_v403.py`（含 50KB 之后改写必须被检出、清单外新增文件必须被判否）。

> ⚠️ **校验和清单不是签名。** 它能发现意外损坏（磁盘故障、同步冲突、复制中断）
> 与「只改文件不改清单」的篡改；若攻击者能**同时**改写文件与清单，清单无法阻止。
> 本文件不做「已防篡改」的表述 —— 那是签名才能提供的性质，本技能没做签名。

### 权限收敛 `harden`（V4.0.3 新增）

`harden <workspace>`（别名 `hd`）把敏感目录收敛为 **目录 0700 / 文件 0600**：
默认只列出目标与当前权限，`--execute` 才真正 `chmod`。

- 覆盖：记忆目录、快照目录、配置中的备份目录。
- **仅 POSIX 生效**：Windows 的 `os.chmod` 只有只读位、没有权限位语义，
  因此该平台明确返回 `supported=false`（提示「不适用」），
  **而不是跑一遍代码就当已经保护**。
- 快照 / 备份 / 导出包在落盘后**自动**收敛（best-effort，失败只记告警、不阻断主操作）。

### 确认门（确切行为，勿误读）

| 层级 | 覆盖命令 | 行为 |
|------|----------|------|
| 默认预览 | `auto-clean` / `cache-clean` / `dedup` / `scan` / `govern` / `compact` | 不带 `--execute` 只出清单，不落盘 |
| `--execute` 才落盘 | 上述命令 + `import` / `restore` / `clean` / `archive` / `harden` | 显式 opt-in（`harden` 不带 `--execute` 只预览目标） |
| 交互式二次确认 | `clean` / `dedup` / `import` / `archive --execute` / `backup --restore --execute` / `snapshot --restore --execute` | 需输入「同意 / y」；**非 TTY 直接拒绝**；`--force` 可显式跳过（有意的自动化逃生门） |
| 机器可读模式 | 上述全部 | `--json` 下**不打印任何人类提示**，直接返回 `{"status":"cancelled","reason":"confirmation_required"}` —— 混入散文会让下游 JSON 解析失败；该模式唯一放行方式是 `--force` |

*V4.0.3 修正*：此前 `import` / `archive` / `backup --restore` / `snapshot --restore`
**没有任何交互确认**，非 TTY 脚本调用即直接写入。SKILL.md 当时声称「必须 `--execute`」，
而 `import` 连 `--execute` 参数都不存在 —— 又一处「写了但没验」的声明，已一并改正。

## 七、明确不做的事（避免误解）

- **不做**记忆内容的语义审查、敏感信息脱敏或加密。记忆按原文落盘、按原文导出。
- **不做**注入拦截 —— 本技能是本地文件工具，不能也不会拦截宿主 Agent 的上下文注入。
- **不提供**导出加密 —— Python 标准库 `zipfile` **不支持写加密 ZIP**。`export` 产出的
  ZIP 是明文；作为折中，POSIX 下产物权限收敛为 0600，请自行加密保管（如 `gpg` / 7z）。
- **不做**密码学签名 —— 见 §五：`SHA256SUMS` 是校验和清单，不是签名。
- **不做** Windows ACL 加固 —— 只报「不适用」，不假装完成。
- **不修改**工作区之外的任何文件（工作区边界校验覆盖所有读写路径）。

## 八、已知残余风险（不含未验证的缓解承诺）

| 风险 | 现状 | 说明 |
|------|------|------|
| 校验和清单非签名 | 设计如此（§七） | 能发现意外损坏与「只改文件不改清单」的篡改；能同时改写二者的攻击者不可防 |
| 导出 ZIP 为明文 | 标准库无法写加密 ZIP | POSIX 下产物收敛 0600；加密需用户自行处理 |
| Windows 无 POSIX 权限位 | `harden` 明确返回不适用 | 未实现 ACL 加固；报「不适用」好过假装已保护 |
| `--force` 可跳过确认 | 有意为之（自动化逃生门） | 仅影响本机、仅影响本工作区；需显式传参，不会误触发 |
| 本机同用户可读取记忆 | 无法防御 | 同用户身份下任何进程都能读工作区文件，属宿主边界 |

*V4.0.2 时此表原有 6 项，其中 4 项已在 V4.0.3 收敛*（交互确认门缺失、目录权限未收敛、
备份无完整性清单、备份篡改无检测）；**剩余 5 项为设计选择或宿主边界，本技能不做或做不到。**
