# Bug 诊断（Android 版）

针对疑难 bug 的纪律。除非有明确理由，否则不许跳阶段。

开始探索代码库时，项目存在 `.qoder/context/`、CONTEXT.md 或 docs/ 业务文档时先读，建立相关模块的心智模型。

## 脱敏（Redact）

本模块会展示命令、输出与抓包产物。**先脱敏**：密钥/token/手机号等敏感信息一律写 `<REDACTED>`。抓包文件带鉴权头：只引用携带信号的行。若脱敏后的信息不足以诊断，明说并向用户索要。

## 阶段 1：构建反馈回路

**这是本模块的灵魂**，其他都是机械步骤。如果你有一个**紧致的**通过/失败信号（能在这个 bug 上变红），你迟早能找到根因——二分、假设验证、插桩都只是消耗这个信号。如果没有，盯着代码看多久都没用。

在这里投入不成比例的精力。**激进一点，有创造力一点，拒绝放弃。**

### Android 构造反馈回路的方式（大致按此顺序）

1. **失败的单测**：`./gradlew :module:testDebugUnitTest --tests "..."`，JUnit/Robolectric 在能触达 bug 的接缝上写失败用例（见 references/02-tdd.md 的接缝表）。秒级跑完——首选。
2. **崩溃重放**：把 crash 堆栈变成回路的"红"。拿到原始堆栈（logcat / Crashlytics 后台导出 / bug 附件）；release 包先还原：用 `retrace`（R8/ProGuard 的 mapping.txt 在 `app/build/outputs/mapping/release/`）把混淆堆栈翻译回源码行列；然后本地断点复现。
3. **日志回路**：触发路径打点（`Log.d` 带前缀），复现后立即 `adb logcat -d` 收集 / 实时 `adb logcat | grep <前缀>` 过滤。
4. **adb CLI 回路**：`adb shell am start -n <包名>/<Activity> --es key value` 带参冷启；`adb shell am start -a android.intent.action.VIEW -d "<深链>"` 模拟唤起；`adb shell input tap x y` 模拟点击。可脚本化重复执行。
5. **网络重放**：Charles/mitmproxy 抓到请求后原样重放（curl），隔离服务端因素；OkHttp 可用拦截器把响应录进单元测试。
6. **Espresso/UI Automator**：录制或手写自动化走完触发路径，断言页面状态。
7. **fuzz/随机输入**："偶发错误输出"类 bug，跑 1000 组随机输入找失败模式（特别适合解析器、格式化、参数处理）。
8. **二分回路**：bug 出现在两个 commit/版本之间，自动化"检出 → 安装 → 验证 → 重复"，供 `git bisect run` 使用。
9. **新旧版本差异回路**：旧版 APK 与新版并排装两台设备（或 `-r` 覆盖安装），同输入 diff 行为差异。
10. **人工回路（最后手段）**：必须人手操作时，写结构化脚本驱动人执行并回传结果。

回路建对，bug 就修好了 90%。

### 收紧回路

把回路当产品打磨。有了回路之后，**收紧它**：

- 能更快吗？（`--tests` 只跑单类、adb 脚本跳过启动引导、mock 掉无关初始化）
- 信号能更尖锐吗？（断言具体症状——"应有 3 条数据实际 1 条"，而不是"没报错"）
- 能更确定吗？（固定系统时钟/冻结网络、固定数据、隔离环境）

30 秒的偶发回路约等于没有回路；2 秒的稳定回路是调试超能力。

### 非确定性 bug（偶发崩溃/竞态/ANR）

目标不是干净的复现，而是**更高的复现率**：循环触发 100 次、并行、加压、收窄时间窗、注入延迟。50% 偶发的 bug 可以调试；1% 的不行。持续提高复现率直到可调试。

Android 偶发问题常规加压手段：开发者选项 **"Don't keep activities"**（不保留活动）放大重建问题、**后台进程限制**调到最小、Network Link Conditioner / 限速弱网、低内存触发（连续开大型 App）、快速连续触发路径、大列表快速滚动。

### 确实建不出回路时

停下来，明说。列出试过的方法，向用户索要：(a) 能复现的设备/系统版本（**具体到厂商 ROM 与 Android 版本**），(b) 脱敏后的产物（完整 logcat、retrace 后的崩溃堆栈、带时间轴的录屏），或 (c) 线上临时插桩的许可。**没有回路，禁止进入假设阶段。**

### 完成标准：一个会变红的紧致回路

阶段 1 完成的标志：你能说出**一条命令/一个操作**（测试调用、脚本路径、adb 命令），且**已实际跑过至少一次**（展示调用与脱敏输出），满足：

- [ ] **可变红**：驱动真实的 bug 代码路径，断言**用户描述的确切症状**——修好后能变绿。不是"跑完不报错"，而是能抓住这个特定 bug。
- [ ] **确定性**：每次运行结论一致（偶发 bug：复现率足够高且固定条件）。
- [ ] **快**：秒级，不是分钟级。
- [ ] **agent 可跑**：无需人值守；必须人参与的走结构化人工回路脚本。

如果你发现自己在回路存在之前就在读代码建理论——**停下：直接跳假设正是本模块要防止的失败模式。** 没有可变红的回路，不进阶段 2。

## 阶段 2：复现 + 最小化

跑回路，看着它随 bug 出现变红。确认：

- [ ] 回路复现的是**用户描述的**失败模式，不是恰好附近的另一个失败。搞错 bug = 搞错修复。
- [ ] 失败可多次复现（偶发 bug：复现率足够高）。
- [ ] 已捕获确切症状（报错信息、错误输出、卡顿时长），供后续阶段验证修复。

### 最小化

变红后，把复现场景缩减到**仍然变红的最小场景**：输入、调用方、配置、数据、步骤，**一次砍一个**，每砍一刀重跑回路，只留下对失败有支撑作用的部分。UI 类 bug：逐步剥离页面/组件层级，直到只剩最小的可复现渲染。

为什么值得：最小复现缩小阶段 3 的假设空间（剩下的可怀疑对象更少），并在阶段 5 直接变成干净的回归测试。

完成标准：**剩下的每个元素都有支撑作用**——删掉任何一个回路就变绿。

未复现 + 未最小化，不准前进。

## 阶段 3：假设

先产出 **3~5 个排序的假设**，再验证任何一个。只产一个假设会锚定在第一个看似合理的想法上。

每个假设必须**可证伪**：写明它的预言。

> 格式："如果 <X> 是根因，那么 <改 Y> 会让 bug 消失 / <改 Z> 会让它恶化。"

写不出预言的假设是玄学：丢弃或磨尖。

**验证前把排序后的清单给用户看。** 用户常有领域知识能瞬间重排（"昨天刚上过 #3 相关功能"），或知道某些假设已排除。廉价的检查点，省大量时间。用户不在时不要阻塞——按你的排序继续。

## 阶段 4：插桩验证

每个探针必须对应阶段 3 的某个具体预言。**一次只改一个变量。**

工具偏好（Android）：

1. **断点**：Android Studio 调试器（条件断点 + 表达式求值；含挂起策略仅暂停当前线程，观察多线程竞态）。一个断点胜过十个日志。
2. **针对性日志**：打在能区分假设的边界上（模块边界/网络响应进入点/生命周期回调）。严禁"全量打日志再 grep"。
3. **系统工具**：**LeakCanary**（内存/Context 泄漏）、**StrictMode**（主线程 IO/网络、磁盘违规）、Layout Inspector（视图树）。
4. **线上信号**：Crashlytics/Bugly 堆栈聚类与设备分布（先 retrace）、自定义埋点（注意脱敏）。

**每条调试日志打唯一前缀**，如 `[DEBUG-a4f2]`。收尾时清理 = 一次 grep。带前缀的日志会死，不带前缀的日志永生。

**性能回退分支**：日志通常是错的工具。先建基线测量：**Android Studio Profiler**（CPU/内存/帧时间）、**Perfetto/Systrace**（`adb shell perfetto` 抓 trace）、**Macrobenchmark + Baseline Profiles**（启动与滚动的可复现基准）。⚠️ 测量用 release 构建（debug 有校验与无优化开销）。再二分。先测量，后修复。

## 阶段 5：修复 + 回归测试

**先写回归测试，再写修复**——但仅当存在**正确的接缝**。

正确接缝 = 测试能以调用现场的真实方式触发该 bug。若唯一可用的接缝太浅（bug 需要多层协作，而单测只能覆盖单层），在那写回归测试只会带来虚假信心。

**如果没有正确接缝，这本身就是结论**：记录下来——代码架构在阻止这个 bug 被锁定，标记给架构评审（references/05-architecture-review.md）。

若有正确接缝：

1. 把最小化复现转成该接缝上的失败测试。
2. 看着它失败。
3. 实施修复。
4. 看着它通过。
5. 用阶段 1 的回路对**原始（未最小化）**场景再跑一遍。

## 阶段 6：收尾

宣布完成前必须：

- [ ] 原始复现场景不再复现（重跑阶段 1 回路）
- [ ] 回归测试通过（或"无正确接缝"已记录）
- [ ] 所有 `[DEBUG-...]` 插桩已移除（grep 前缀确认）
- [ ] 临时原型已删除（或移到明确标记的调试目录）
- [ ] 被证实正确的那个假设写进 commit / PR 描述——让下一个调试者受益
