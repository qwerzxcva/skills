# 需求拷问（Android 版）

对用户的需求/方案进行不懈追问，直到双方达成共享理解。将其建模为**设计树**：每个决策都挂着依赖它的子决策。

按**轮次**推进。**前沿（frontier）** = 所有前置条件已确定的决策——即现在就能问、不需要猜测未决答案的问题。**一轮问完整个前沿**：给每个问题编号，并附上你的推荐答案。然后等用户回答，再进入下一轮。

轮次格式：

```
❓ **Q1** - **<问题标题>**: <问题正文，可多段，含候选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文>

➡️ <你的推荐答案>
```

每轮回答都会重塑设计树：已确定的决策把前沿向外推，解锁依赖它们的问题。重新计算前沿，再问下一轮。**依赖本轮未决问题的子问题，属于后面的轮次，不属于本轮**。

## Android 必查维度（前沿覆盖检查单）

生成问题时，对照以下维度确认没有漏掉关键分支：

**状态维度**
- 登录态：未登录/多账号切换/ token 过期时的表现？
- 权限：涉及系统权限（相机/定位/存储/通知/蓝牙）？AndroidManifest 静态声明 + 运行时动态申请如何配合？用户拒绝后降级策略？**targetSdk 升级是否改变了权限语义**（如 Android 13 通知权限、Android 14 部分照片访问）？
- 网络：断网/弱网表现？失败重试？与推送长连接的关系？
- 生命周期：页面进入后台/锁屏/进程被杀后回到前台，页面状态如何恢复（savedInstanceState / ViewModel / SavedStateHandle）？旋转屏幕/配置变化后重建的表现？

**设备维度**
- minSdk / targetSdk / compileSdk 范围？不同 API 级别的行为差异与兼容分支？
- **厂商 ROM 差异**：小米/华为/OPPO/vivo 的推送通道、保活限制、自启动管理、权限弹窗文案差异？
- 设备形态：折叠屏展开/折叠、平板横屏、大屏窗口模式？
- 系统主题：深色模式/跟随系统切换？字体放大（sp）与超大字号下的布局？
- 架构：ABI 范围（arm64-v8a / armeabi-v7a / x86_64）？包体积影响？

**数据维度**
- 空态/错误态/加载态长什么样？
- 数据量级：列表 100 条和 10 万条的差异（分页/加载策略/性能）？
- 数据一致性：本地 DB（Room）/SP/DataStore 与服务端冲突时以谁为准？

**入口维度**
- 页面从哪些入口可达（首页跳转/通知栏 push/深链 App Links/桌面快捷方式/其他 App 唤起/分享接收）？
- 入口参数差异？登录墙在哪挡？冷启动 vs 热启动路径差异？

**性能预算**
- 启动时间/页面打开/滑动帧率有没有量化要求？超出预算怎么办（降级/异步/延迟加载）？

**事实自己查，不要问用户**。前沿问题需要代码事实时（现有实现、目录结构、接口定义），自己去读代码/派子代理查。项目存在 `.qoder/context/`、CONTEXT.md 或 docs/ 业务文档时先读。查到之前，依赖该事实的问题归入后续轮次。

**决策才是用户的**：每个决策都摆给用户，等待回答。

**完成标准**：前沿为空——设计树每个分支都走到了，没有任何静默假设。在用户确认达成共享理解之前，不要开始写代码。需求收敛后如需落盘，调用 `references/01-to-spec.md`。
