## 上下文与会话

**Q：右下角那个小圈是什么？数字怎么看？**
它是这个对话「背着多少东西」。比如 `49.4K/1000K` 就是已经背了约 4.9 万 token，这个模型最多能背 100 万。点开还能看分项：是技能/连接器占得多，还是聊天记录占得多——这决定了该怎么治。（动作 B）

**Q：圈过半了怎么办？**
一半左右最好；过了一半就该考虑压缩，或者新开一个会话。任务没做完就先存检查点再压缩。（动作 C、D、F）

**Q：`/compact` 会不会把东西弄丢？**
会丢一点——它是「总结」不是「原样保留」，细节和特殊要求可能被弱化。所以压缩前先让它把目标、进度、约束、改过的文件、没解决的问题、下一步这六项写进工作空间里的文件，再压缩。顺序不能反。（动作 D）

**Q：新开会话还是接着聊？**
同一件事的连续追问、要接着用前面的文件和状态 → 留原会话。圈快满、它开始反复犯同一个错、或者要干一件不相关的事 → 新开，最好开在同一个工作空间里。（动作 F）

**Q：它开始来回重复同一个错误，是模型不行吗？**
通常不是。这往往是对话太长、上下文乱了的信号，新开会话比换模型有效。

## 技能与插件

**Q：技能装多了真的会变慢吗？**
会。每个开着的技能都要把说明书发给模型，装得越多，每次对话一开始就背得越重，模型挑技能时也越容易分心。脚本会告诉你具体哪几个技能最占地方。（动作 A）

**Q：不用的技能要删掉吗？**
不用删，**关掉就行**，随时能再打开。只有正在用的那个别关。

**Q：关完技能怎么还是一样？**
关技能不会让**当前**对话变轻，得**新开一个会话**再看圈里「连接器、MCP 及技能」那项有没有降。

## 模式与模型

**Q：Max 模式该开还是关？**
要反复引用前面的讨论、文件状态、复杂约束 → 开（更费积分）。任务之间互相独立、前面聊的已经用不上 → 关，它会自动帮你压缩。（动作 E）

**Q：Ask / Plan / Craft 怎么选？**
只是讨论、查资料 → Ask（只看不动，最省）；复杂或有风险的活 → Plan（先出方案再动手）；目标明确要快速产出 → Craft（默认，发消息就消耗积分）。（动作 I）

**Q：换个模型会不会快一点？**
任务做到一半别换：换模型可能用不上之前的缓存，还可能丢信息。一定要换就先 `/compact` 再换；想比较模型就新开会话。如果换了也没变快，问题就不在模型。（动作 K）

**Q：积分掉得太快怎么办？**
先看 Max 模式是不是开着；再按任务选倍率低的模型（以模型下拉里当前显示的倍率为准）；Thinking 模式和专家团都更费积分。具体额度和刷新周期请看官方渠道，这里不给数字。

**Q：写代码 / git 乱了，是不是 WorkBuddy 干不了？**
先看对话区顶部是不是「代码开发」场景。这个场景自带 Git 分支管理和 Worktree 并行任务，场景不对就是在用一套不适合写代码的配置。（动作 G）

## 报错与网络

**Q：报了一个错误码，什么意思？**
对 SKILL.md 的错误码表，一码一处置。表里没有的码，如实说「这个码没有公开说明」，然后走反馈。

**Q：连接器时好时坏？**
多半是那个外部服务的问题，不是 WorkBuddy 本身慢。看它返回什么码：401 重新授权、429 放慢调用、5xx 等几分钟再试。

**Q：都试过了还是慢？**
能在客户端这边调的已经调完了，剩下的调不动。生成一段反馈文案，从左下角头像 → 帮助与反馈 → 意见反馈提交，记得勾「上传日志」。

## 这个技能本身

**Q：它会改我的设置或文件吗？**
不会。体检脚本全程只读，不联网、不上传；唯一写的是系统临时目录里的一份「改前基线」，用来算改完后降了多少。

**Q：脚本提示「没找到 WorkBuddy 的数据」？**
说明 WorkBuddy 不在这台电脑上，或者数据放在别处。不影响诊断，只是改成问一句答一句；数据在别处的话可以设环境变量 `WORKBUDDY_HOME` 指过去。

**Q：写的菜单位置和我界面上不一样？**
WorkBuddy 更新后位置可能变了，以你眼前的界面为准。
