## 铁律：没判据不许定性到 L2~L6

**禁的是「没判据的猜」，不是「没走完问答清单」。** 用户给了判据，那一层就能定，一个问题都不用问。备用问题全答了但全是「不知道」，同样不许定性。

**判据分两档，说法不一样，别混用：**

| 判据档位 | 例子 | 你可以说 |
|---|---|---|
| **实测数据** | 圈读数 `680K/1000K`、圈内**分项占比**、错误码 `11115` | 「**就是** L几」 |
| **代理判据** | 扫描读出的**安装计数**（常驻技能数、插件数、MCP 工具定义数） | 「**大概率是** L几」 |
| **症状描述** | 「时好时坏」「越聊越慢」「又慢又费积分」 | 「**大概率是** L几」，并说还缺什么才能确认 |

**为什么扫描的计数只算代理判据**：L2 的精确判据是圈里「连接器、MCP 及技能」相对其他三项的**占比**，而那个分项占比**只在界面上算，本地数据里没有**——扫描只能读出装了多少个。装得多不等于那一项占比一定最大，中间隔着一步推断。

**所以要把 L2 钉死成「就是」，只有一个办法**：让用户点开圈、展开看分项。**只在他追问「你怎么确定」或者按代理判据改完没效果时才这么做**，别一上来就要他去点。

**把「大概率」说成「就是」，是这里唯一的错法。**

**L1 是铁律的明文例外**：判 L1 只需要一个输入——这活是什么，原话里通常就有；处方是「切个场景」，代价接近零。所以 **L1 命中信号一出现就当场定性开处方**。反过来不成立：**L1 排除 ≠ 可以接着定性到别的层**。

**定性完成前只能给三样**：那一个路由动作、L1 判定、**存检查点**（仅当他提到「任务没做完 / 不想丢」）。其余一律等判据——没判据就给「关知识库」「拆任务」「换模型」「新开会话」，是在猜。

## 30 秒分诊表

| 用户的症状原话 | 最可能 | 去哪层 |
|---|---|---|
| 写代码 / 改多个文件 / git 出问题；或办公活却开着代码场景 | **任务与场景错配**（最高频） | L1 |
| 装了一堆技能 / 挂了知识库 / 工作空间文件多 / 传了长表格 | 上下文负担 | L2 |
| 刚开始挺快，聊久了越来越慢；圈圈快满；模型开始循环出错 | 会话堆积 | L3 |
| 一句话交代一大坨活，转很久没动静；或该讨论时它直接动手改文件 | 颗粒度与模式 | L4 |
| 出字本身就慢但任务很简单；积分掉得快；越换模型越乱 | 模型 / 积分侧 | L5 |
| 报网络类错误码；连接器时好时坏；或 L1~L5 全排掉还是慢 | 网络 / 连接器 / 不可控 | L6 |

**多条同时命中时，永远从 L1 往下做**——L1 修复成本最低、收益最大。

## L1 任务与场景错配（先查这个）

**两个分叉，按顺序查：**

### 分叉一：场景模式对不对（先查，几乎零成本）

场景模式在**对话区顶部**切换，选好场景后**自动加载该场景的最佳配置（模型、技能、专家）**。四个场景：代码开发 / 日常办公 / 设计创意 / 媒体运营。

| 用户在干的活 | 该在哪个场景 |
|---|---|
| 日常开发、网站开发、Agent 应用、Skill 开发 | **代码开发** |
| 文档处理、数据分析及可视化、深度研究、幻灯片 | **日常办公** |
| 网站设计、移动端 App、PPT 设计、交互原型、品牌设计、3D 模型 | **设计创意** |
| 内容创作与运营 | **媒体运营** |

**在错的场景里干活 = 每一轮都在为用不上的配置付费。** 写代码却停在「日常办公」场景，加载的是文档类的模型和技能；反过来也一样。

**git 相关的抱怨不要直接判成「WorkBuddy 干不了」**——代码开发场景自带 **Git 分支管理**（分支展示与安全切换、独立本地终端和后台命令运行面板）和 **Worktree 并行任务**（同一工作区并行处理多个开发任务，代码改动互不干扰）。git 乱了的第一处方是**切到代码开发场景用这套面板**，不是换产品。

### 分叉二：任务规模超没超过单次会话能扛的量

这不是「这个产品行不行」的判断，是个容量问题：一次任务要同时顾及的文件和约束太多时，表现就是反复读、反复确认、来回试。

| 任务规模 | 怎么安排 |
|---|---|
| 单个文件、几处改动、一个脚本、一个网页 | 一个会话跑完 |
| 多模块、大规模重构、要通盘设计 | **拆成多个任务**，每个任务单独一个会话，用检查点文件串联 |

**和 L4 怎么分**：这两层症状很像（都是「交代完转很久没动静」），但拆法相反，别拿错。

| | L1 分叉二 | L4 |
|---|---|---|
| 问题出在 | **范围**——要碰的文件和约束太多 | **步骤**——一次交代了太多步 |
| 拆法 | 拆成**多个会话**，检查点文件串联 | 同一会话里**分多轮**推进 |

**判别动作**：把这活的第一步单独拎出来问。第一步很快出结果 → L4，范围没问题，只是一次说太多。第一步光是开始就得先读一大堆文件 → L1，范围本身就超了。

**命中信号（出现任意一条即判 L1——铁律的明文例外，不用等补问）：**

- 用户在干的活和当前场景模式对不上
- 用户说的活里有「整个项目」「大规模重构」「多模块」——规模超过单次会话，该拆
- 抱怨里出现 git 问题。**不知道用户当前在哪个场景也照判 L1**——「当前是哪个场景」本身就是第一个处方动作，不是判定的前置条件
- 它反复读同一批文件、反复问你文件在哪

**处方顺序**：先切对场景 → 还慢再看任务规模是不是该拆 → 给出怎么拆。**不要顺势评价产品行不行，也不要建议他改用别家工具**——用户问的是怎么跑顺手上这件事。

**别给的处方**：让用户「把提示词写得更清楚」来解决场景错配。提示词改的是表达，改不了这个场景加载了哪套配置。

**L1 处方给完，本轮诊断就结束了。** 不要顺手预判 L2~L6——你还没拿到判据。把其余层标〔待测〕。

**但要留好衔接**：结尾补一句「切完还是慢的话，回来告诉我两件事——是一直慢还是聊到后面才慢、工作空间里文件多不多 / 挂没挂知识库」。这两问正好补齐 SKILL.md 备用清单的第 3、5 问，用户真回来时你就能直接定性到 L2 或 L3，不用从头再问一轮。

## L2 上下文负担

**判据直接来自上下文圈的分项展开**（这是官方给的诊断工具，比任何自测都准）：

| 哪一项占得多 | 是什么 | 动作 |
|---|---|---|
| **连接器、MCP 及技能**占比高 | 常驻开销：技能装太多 | 关掉不用的技能（playbook 动作 A） |
| **系统提示词 / 工具及子智能体**占比高 | 常驻开销，同上 | 同上 |
| **对话消息**占比高且会话刚开 | 挂进来的材料太重 | 收窄材料 |
| **对话消息**占比高且聊了很久 | 会话堆积，不是 L2 | 去 L3 |

**技能为什么吃窗口**：每个技能的定义都要发给模型，模型得知道装了哪些技能、各自干什么、什么时候调用。装得越多，承载这些说明就要占掉一块窗口，同时模型选择时的干扰也更大。

**另外两个常被忽略的来源**：

- **工作空间文件太多**——AI 按文件名和路径匹配，文件太多会增加干扰。处置：不相关的文件移出工作空间、用清晰的目录结构、提问时带上具体路径或文件名前缀
- **Memories 画像每次新会话自动注入**（`<memory>` 块）。敏感或独立的任务可以在设置 → 记忆临时关掉总开关

**处方**：
- 关掉长期不用的技能（**关，不是删**）
- 一次只挂当前这件事用得上的材料，别把知识库当常驻背景
- 长表格先裁到相关行列再传
- 提示词里别塞无关内容——会挤占窗口、稀释核心信息

## L3 会话堆积

**红线**：用量保持在**一半左右**最好；**超过一半就该考虑压缩或新开任务**。

**官方的新会话判据**（比什么自测都直接）：

| 情况 | 怎么办 |
|---|---|
| 圈圈快满（官方举例 `900K/1000K`）／**模型陷入循环反复出错**／两件事之间没有关联 | **开新会话**，最好开在**同一工作空间**（文件背景还在） |
| 同一个任务的连续追问／前面的历史文件、状态需要延续 | **留原会话** |
| 任务没做完但对话太长 | 先存检查点 → 再 `/compact`（**顺序不能反**） |

「模型循环出错」是个容易被当成模型问题的 L3 信号——反复调同一个工具、反复给同样的错误回复，往往是上下文已经乱了，不是模型不行。

**Max 模式要一起看**（模型选择下拉顶部）：

- **打开** = 不压缩、保留完整上下文。适合需要**频繁引用之前的讨论、文件状态和复杂约束**的任务，**但可能增加积分消耗**
- **关闭** = WorkBuddy 在某个时机自动帮你压缩，降低窗口使用。适合任务**相对独立**，或**已经积累了大量不再重要的讨论**

用户抱怨「又慢又费积分」时，先问 Max 模式是不是开着——开着跑一堆独立小任务是纯浪费。

**`/compact` 前必须先存检查点**。压缩**不是完全无损的**——细节、特殊约束和中间状态都可能在总结时被弱化。让 Agent 整理六项——当前目标／已经完成的内容／重要约束／修改过的文件／尚未解决的问题／下一步动作——并**写入工作空间里的文件**。模板在 [playbook.md](reference/playbook.md) 动作 D。只发在对话里的检查点会跟着一起被压掉。

**官方对长会话的其余处置**：把关键结论复制到新会话；长任务拆成多轮短会话；重要结论让 AI 写入记忆或文件，不依赖对话历史。

## L4 颗粒度与工作模式

**症状**：一句话交代一大坨活，长时间转圈没有中间产出；或者只想讨论方案，它上来就改文件。

**工作模式三档**（入口在对话框「+」旁，权限递增）：

| 模式 | 权限 | 什么时候用 |
|---|---|---|
| **Ask** | 只看不动，纯问答 | 查资料、梳理选题、讨论方案、正式执行前明确需求。**不加载执行类工具，省上下文开销** |
| **Plan** | 先出方案再执行 | 复杂任务、高风险操作、需要对齐方案 |
| **Craft** | 直接干活（默认） | 任务明确、要快速产出。⚠️ **发消息即消耗积分** |

**处方**：
- 讨论阶段切 Ask——这是 L4 最省的一刀，省窗口也省积分
- 复杂任务先走 Plan，确认方案再让它动手
- 复杂问题拆成多轮：先让它做第一步，确认方向对了再推进
- 指令本身乱 → 用右下角小闪光图标的**优化提示词按钮**
- **结果偏了，补背景比反复重试有效**：别连续重试同样的指令，补一句背景通常一次就能纠正

**边界**：优化提示词治的是表达，治不了 L1 场景错配。

## L5 模型与积分

**先用备用清单第 4 问挡掉**：用户说「换模型也没用」→ 跳过这层去 L6。但要分清：

| 用户原话 | 含义 | 去哪 |
|---|---|---|
| 「换了没变快」 | 模型侧无关 | L6 |
| 「越换越乱 / 换完它忘事了」 | **就是 L5** | 下面 |

**别在任务中途换模型**：官方定性是同一对话里频繁切换**性能会下降，还可能造成信息丢失**——切换后原有提示词缓存不一定能继续复用，且切到窗口更小的模型可能触发压缩或裁剪。同任务用同一模型跑完；一定要切就**先 `/compact` 再切，成本消耗会降低**；想对比模型就**在同一工作空间开新会话**。

**积分掉得快时按倍率选模型**（完整表在 product-facts.md）：编程任务 Deepseek V4-Pro `0.25x`、批量轻量任务 Hy3 preview `0.04x`、不确定用 Auto `0.40x`。另外 Thinking Mode 开启消耗更多积分，专家团消耗是单专家的 3-5 倍。

**卡「思考中」没反应的官方处置**：点发送处按钮停止任务 → 切换模型重发；仍不行就拆小任务 / 检查网络。

**额度的具体数额与刷新周期不许给。** 让用户去官方渠道查——编一个比不给更糟。

## L6 网络与服务端

**这层一半能修，一半不能。先把能修的那一半查完，再下「调不动」的结论。**

**怎么进这一层**：L1~L5 逐层排掉之后还是慢——换模型没用、换会话没用、关技能没用、压缩也没用。它是「剩下的」，不是靠某个正面信号判出来的。

### 能修的那一半：按四级往下查

**一级 · 本机网络**

对话出错时用「检查网络」快捷入口；较新版本的客户端还自带自检工具，环境排查先跑它。

**二级 · 代理**

`3002` / `3003` / `3007` 都是网络环境问题（公司网 / 家庭网限制）。处置：

- 公司网 → 找 IT 排查，通常是防火墙或白名单
- 家庭网 → 关闭网络代理；客户端内置代理切换，**建议设成「跟随系统」**

**三级 · 连接器 / MCP**（挂了连接器才查这级）

慢或失败集中在某个外部服务上时，看它返回什么码：

| 码 / 现象 | 处置 |
|---|---|
| `401` | 连接器 token 过期 → UI → 连接器 → 重新授权 |
| `403` | 权限不足 → 查账号是否开通该服务 |
| `404` | URL 错或服务下线 |
| `429` | 被限流 → 降低频率，**请求间隔加到 2-3 秒** |
| `500` / `502` / `503` | 服务端内部错误 → **等 2-5 分钟再试**，仍失败则服务可能已下线 |
| `连接超时` | 查防火墙，**timeout 调到 600000**（10 分钟） |

部分服务的 token 需定期刷新（通常 2 小时）。**连接器时好时坏、间歇性失败，多半是这一级，不是 WorkBuddy 本身慢。**

**四级 · 模型侧限频**

`6003` / `6004` 是请求频率受限（专业版也会出现）→ 切换模型重试。

### 修不了的那一半

上面四级都排掉之后，**就到此为止**。

**处方**：**明确告诉用户「查到这里为止，剩下的客户端侧调不动」**——这句话比让他继续试设置项有价值。

**要上报**：左下角头像 → 帮助与反馈 → 意见反馈，**上传截图 + 勾选上传日志**。版本号在桌面端侧栏能看到，抄进反馈里。

> **成因分两种，别看岔。** 上面四级里的成因（`429` 是被限流、`401` 是 token 过期）**都有错误码作判据，可以照说**。这条禁令针对的是**四级全排掉、一个码都没有**之后的那部分——「服务端排队」「高峰期限流」「内容审查拖慢」没有任何可复现判据，说出口就是把猜测包装成结论。**有码就说成因，没码就只说「客户端侧调不动」。**
