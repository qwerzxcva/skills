## 零风险体检

这两个动作**可逆、不丢数据、不依赖诊断结论**，可以在问诊的同时让用户先做：

1. 点右下角灰色小圈，**并展开看分项**（动作 B）——一个动作同时给出总量和结构
2. 关掉长期不用的技能（动作 A）

第三样安全垫是**存检查点**（动作 D），仅在用户提到「任务没做完 / 不想丢」时提前给。

**做完这些不等于诊断完。** 定性结论仍要等拿到判据再下（见 [layers.md](layers.md) 铁律）。

## A. 关掉闲置技能

**属于哪层**：L2，常驻开销。

**为什么有效**：每个技能的定义都要发给模型，模型得知道装了哪些技能、各自干什么、什么时候调用。装得越多，承载这些说明就要占掉一块窗口；同时技能越多，模型判断「这次该用哪个」时的干扰也越大。

**怎么做**：打开**技能管理页**，把长期不用的技能**关掉（不用删，关掉即可）**，需要时再打开——技能是可以随时开关的。

**关键**：关开关不是删除，可逆，所以可以放心大胆地关——这是本手册里唯一一个「宁可多关」的动作。

**判据（顺序不能乱）**：

1. **必须新开一个会话**再点开上下文圈——当前会话不会自动变轻，在原会话里看等于没测
2. 看「连接器、MCP 及技能占用」这一项**有没有下降**

| 结果 | 说明 | 下一步 |
|---|---|---|
| 降了，也变快了 | 处方对 | 结束 |
| 降了，但还是慢 | 常驻开销这层确实排掉了 | 回 SKILL.md「第二轮」第 1 步，给顺带发现那条 |
| **没降** | **处方没生效，不是判断错了** | 确认技能是不是真的关上了，别急着换层 |

**坑**：当前任务正在用的技能别关，关完这轮任务会突然「不会做事了」。

## B. 读上下文圈并展开分项

**属于哪层**：不是一层，是 **L2 和 L3 的共用判据来源**。定性前读一次，改完再读一次。

**怎么做**：点击对话框**右下角的灰色小圈**。很多人见过但没点开过——**点开才是重点**。

**点开后能看到六项**：

1. 当前上下文的使用比例
2. 已使用量和模型窗口上限
3. 系统提示词占用
4. 工具及子智能体占用
5. 对话消息占用
6. **连接器、MCP 及技能占用**

**读数怎么解释**：形如「4.9% · 49.4K/1000K」= 当前会话已用约 49.4K token，**该模型的上下文窗口上限是 1000K**。

> 分母**就是当前所选模型的窗口上限**，可以这样告诉用户。但**不同模型的窗口上限不一样**——不许把某一次看到的分母说成「WorkBuddy 的上限」。

**红线**：用量保持在**一半左右**最好；**超过一半就该考虑压缩上下文或新开任务**。

**分项怎么读**（这是本手册最有价值的一张表）：

| 哪项占得多 | 说明什么 | 去哪 |
|---|---|---|
| **连接器、MCP 及技能** | 常驻开销重，技能装太多 | 动作 A |
| 系统提示词 / 工具及子智能体 | 常驻开销，同上 | 动作 A |
| 对话消息，且会话刚开 | 挂进来的材料太重 | 收窄材料 / 动作 H |
| 对话消息，且聊了很久 | 会话堆积 | 动作 C / E / F |
| 都不高但还是慢 | 不是上下文问题 | 回 [layers.md](layers.md) 的 L1 / L5 / L6 |

**只看比例不点开，等于放弃了区分常驻开销和会话堆积的唯一办法。**

## C. /compact 压缩对话

**属于哪层**：L3。

**什么时候用**：对话太长、**但不想新开会话**（任务还没做完）。

**怎么做**：对话框里直接发这条斜杠指令 `/compact`。WorkBuddy 会把当前上下文交给模型**主动压缩**——总结前面聊过的内容、替换掉原始对话记录、腾出窗口继续跑。

**为什么值得主动压**：主动压缩比等窗口接近上限后**被动裁剪**更可控。

**判据**：压缩后上下文圈读数明显下降，且后续回复的首字延迟回落。

**坑（重要）**：压缩**不是完全无损的**——细节、特殊约束和中间状态都可能在总结时被弱化。所以复杂任务在压缩前**必须先存检查点**（动作 D）。

**什么时候不该用**：任务已经做完、下一件事无关——那种情况直接新开会话（动作 F）更干净。

---

## D. 压缩前先存检查点

**属于哪层**：L3，动作 C 和 K 的前置步骤。

**什么时候必做**：复杂任务、跨多个文件、有明确约束条件的任务，在 `/compact` 或换模型之前。

**怎么做**：让 Agent 整理一份「任务检查点」，并**写入工作空间里的文件**。

**检查点模板**（官方六项，可以直接把这段发出去）：

```
在压缩对话之前，先整理一份「任务检查点」，写入当前工作空间里的一个文件：

1. 当前目标
2. 已经完成的内容
3. 重要约束
4. 修改过的文件
5. 尚未解决的问题
6. 下一步动作

保存完告诉我文件路径，我确认后再压缩。
```

**为什么必须写进文件**：这样即使摘要漏掉细节，**新一轮上下文也能重新读到任务状态**。只发在对话里的那份会跟着一起被压掉。

**判据**：文件存在、六项齐全，且第 3 项（重要约束）里能看到你确实提过的要求。官方点名说压缩会弱化「特殊约束」，这一项丢了之后最贵。

## E. Max 模式开还是关

**属于哪层**：L3。**这是最容易被忽略的一个开关。**

**位置**：模型选择下拉的**顶部**。

| 状态 | 行为 | 适合 |
|---|---|---|
| **打开** | 不压缩，保留完整上下文 | 需要**频繁引用之前的讨论、文件状态和复杂约束**的任务。可以保留更多信息，**但可能增加积分消耗** |
| **关闭** | WorkBuddy 会在某个时机自动帮你压缩上下文，降低窗口使用 | 任务**相对独立**，或者**已经积累了大量不再重要的讨论** |

**什么时候该怀疑它**：用户抱怨「**又慢又费积分**」。开着 Max 模式跑一堆互不相干的小任务是纯浪费——每一轮都在背完整历史，还按完整历史计费。

**判据**：关掉 Max 模式后跑同类任务，上下文圈不再单调爬升，积分消耗速度下降。

**反向的坑**：需要长期记忆的复杂任务把 Max 关了，会出现「它怎么又忘了」——那不是模型变笨，是自动压缩把细节压掉了。这种情况应该开着 Max，或者配合动作 D 存检查点。

**中间情况——单个连续大任务，但用户嫌费积分**：这种**不许替用户直接关**。关闭条件有两个：「任务相对独立」和「已经积累了大量不再重要的讨论」——**后一条对连续大任务也成立**。所以先问清它现在是开是关、前面那些讨论还需不需要引用，再给用户两条路自己选：

| 选择 | 代价 |
|---|---|
| 保持开着 | 继续费积分，但细节不丢 |
| 存好检查点（动作 D）再关掉 | 省积分，但压缩后要靠检查点文件找回上下文 |

**判断谁更划算的关键是「这个任务还要跑多久」**——快收尾了就保持开着跑完，还要跑很久就存检查点后关掉。

## F. 新会话还是留原会话

**属于哪层**：L3。

**判据**：

| 情况 | 怎么办 |
|---|---|
| 上下文圈圈快满了（官方举例：显示 `900K/1000K`） | **开新会话** |
| **模型陷入某种循环，反复出错、任务再也完不成** | **开新会话** |
| 两件事之间没有关联（刚在做调研，突然想聊别的） | **开新会话** |
| 同一个任务的连续追问 | **留原会话** |
| 前面的历史文件、状态需要延续 | **留原会话** |

**「模型循环出错」这一条最容易误判**：反复调同一个工具、反复给同样的错误回复，看起来像模型不行，实际往往是上下文已经乱了。换模型解决不了，开新会话才能。

**新会话最好开在同一个工作空间**——这样仍然可以读取项目文件和背景资料，相当于工作台没变，但给任务换了个更清醒的脑子。工作空间在**对话框左下角的「选择工作空间」下拉**里切换。

**长会话的其余处置**：把关键结论复制到新会话；长任务拆成多轮短会话；重要结论让 AI 写入记忆或文件，不依赖对话历史。

**和 `/compact` 怎么选**：

| 情况 | 用哪个 |
|---|---|
| 任务没做完，只是对话太长 | `/compact`（动作 C，先存检查点） |
| 任务做完了，下一件事无关 | 新开会话 |
| 任务做完了，下一件事是延续 | 新开会话 + 把检查点文件带过去 |

## G. 切对场景模式

**属于哪层**：L1。**成本最低、最常被忽略的一刀。**

**位置**：对话区顶部切换。选好场景后会**自动加载该场景的最佳配置（模型、技能、专家）**。

**「哪个活该切哪个场景」的对照表在 [layers.md](layers.md) 的 L1 章节**，判定在那里做，这里不重复一份——两处各存一份迟早改漏。

**在错的场景里干活 = 每一轮都在为用不上的配置付费。**

**代码开发场景 5.4.0 起还自带两件事**，这两件正好对着最常见的两个抱怨：

- **Git 分支管理**：分支展示与安全切换，提供独立本地终端和后台命令运行面板
- **Worktree 并行任务**：同一工作区并行处理多个开发任务，代码改动互不干扰

**所以用户说「git 被搞乱了」时，第一处方是切到代码开发场景用这套面板，不是判定产品干不了。**

**判据**：切场景后重开任务，快捷方式面板内容随之变化，且同类任务不再反复问「文件在哪」。

## H. 工作空间瘦身

**属于哪层**：L2。

**为什么有效**：AI 搜索工作空间时**按文件名和路径匹配，文件太多会增加干扰**。表现是它找错文件、反复确认、来回读。

**怎么做**（官方三条）：

1. 不相关的文件移出工作空间
2. 用清晰的目录结构分类
3. 提问时**带上具体路径或文件名前缀**，缩小搜索范围

**判据**：同一个问题带上路径前缀再问一次，如果它不再来回找文件 → 确认是这条。

**顺带**：Memories 画像在**每次新会话开始时自动注入**（`<memory>` 块）。做独立或敏感任务时，可以在设置 → 记忆临时关掉总开关——关闭只影响画像注入，不影响本次对话本身的上下文。

## I. 选对工作模式 Ask/Plan/Craft

**属于哪层**：L4。

**位置**：入口在对话框「+」旁。三档权限递增。

| 模式 | 权限 | 用在什么时候 |
|---|---|---|
| **Ask** | 只看不动，纯问答 | 查资料、梳理选题、讨论方案、正式执行前明确需求 |
| **Plan** | 先出方案，确认后再动手 | 复杂任务、高风险操作、需要对齐方案、多人协作 |
| **Craft** | 直接操作文件、生成产物（默认） | 任务明确、要快速产出 |

**Ask 为什么省**：**不加载执行类工具**，省上下文开销。这是 L4 最省的一刀——省窗口也省积分。

**Craft 的代价**：默认模式，**发消息即消耗积分**。

**判据**：同一个讨论型问题，Ask 模式下首字延迟更短、回复更聚焦在方案本身而不是操作步骤。

**坑**：讨论完要真动手时记得切回 Craft，否则会出现「聊得挺好但一个文件都没改」。

## J. 优化提示词

**属于哪层**：L4。

**位置**：对话框右下角**小闪光图标**。作用是把模糊指令改写得更聚焦、少废话，**确认之后再发送**。

**配套的三条写法建议**：

- **复杂问题拆成多轮**：不要一次塞入所有需求。先让 AI 做第一步，确认方向正确再推进
- **只给与任务直接相关的材料**：塞太多无关内容会挤占窗口、稀释核心信息
- **结果偏了，补背景比反复重试有效**：别连续重试同样的指令，补一句背景（「我是做 A 领域的，这个数据给 B 部门用」）通常一次就能纠正

**判据**：增强后的提示词里，动作明确、产出物具体。如果增强完你自己都看不出要交付什么，说明这活本身就该拆。

**治不了什么**：治不了 L1 场景错配。提示词改的是表达，改不了这个场景加载了哪套配置。

## K. 模型怎么选、什么时候别换

**属于哪层**：L5。

### 别在任务中途换模型

**为什么不能频繁切**：同一对话里频繁换模型会让性能下降，还可能丢信息。原因有两个：

1. **提示词缓存**——模型可能会缓存之前处理过的部分内容以降低重复处理成本，但缓存通常与具体模型及服务机制有关，**切换模型后原有缓存不一定能继续复用**
2. **上下文窗口不同**——不同模型支持的上下文长度并不一致。在一个较大窗口的模型里积累了大量内容后切到窗口更小的模型，**就可能触发压缩或裁剪**

**正确做法**：同一任务尽量用同一个模型跑完；一定要切就**先 `/compact` 压缩一遍再切，成本消耗会降低**；想尝试不同模型的效果，**在同一工作空间开新的会话，别在原会话里切**。

**必须换时的顺序**：存检查点（动作 D）→ `/compact`（动作 C）→ 再切。

### 按倍率选模型

倍率 = 相对基准消耗的倍数，`0.40x` = 消耗基准的 40%。

| 场景 | 模型 | 倍率 |
|---|---|---|
| 不确定选什么 | Auto | 0.40x |
| 批量 / 轻量任务 | Hy3 preview | 0.04x |
| 编程任务 | Deepseek V4-Pro | 0.25x |
| 长文档分析 | Kimi-K2.6 | 0.59x |
| 中文写作 / 复杂推理 | GLM-5.1 | 1.06x |
| 性价比折中 | MiniMax M2.7 | 0.26x |
| 看图理解 | GLM-5v-Turbo | 0.95x |

**另外三个吃积分的地方**：Thinking Mode 开启后消耗更多；专家团消耗是单专家的 **3-5 倍**；Max 模式开着费积分（动作 E）。

**外部接入的模型消耗个人 API 额度，不消耗 WorkBuddy 积分**——用户额度紧张且有自己的 API 时，这是一条出路。

### 卡「思考中」没反应

官方处置：**点发送处按钮停止任务 → 切换模型重发**；仍不行就拆小任务 / 检查网络（对话出错时有「检查网络」快捷入口）。

**注意**：这里的「切换模型」是为了绕开模型侧异常（对应错误码 `1001` / `11133` / `14003`），和上面「别频繁切模型」不矛盾——前者是任务已经卡死、要重来，后者是任务正常跑着别乱动。
