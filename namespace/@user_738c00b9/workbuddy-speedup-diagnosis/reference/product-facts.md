**这个文件是白名单，不是参考读物。** 给用户的每一个产品功能、菜单路径、数字，都必须能在下面找到出处。找不到 → 不许说。

## 出处分级

| 标注 | 来源 | 权威度 |
|---|---|---|
| `官方` | WorkBuddy 官方公众号发布的使用技巧文章（2026-08） | **最高。与其他来源冲突时以它为准** |
| `guide:文件:行号` | 《WorkBuddy 使用指南》v2.7.0（适配客户端 5.5.4） | 次级。只在 `官方` 未覆盖的范围内使用 |
| `本机实测` | 在真实安装上直接读出的本地数据结构（客户端 5.6.2 / macOS） | 仅用于扫描脚本。**可能随版本或平台变化**，所以脚本读不到时必须优雅退回问答，不许假设它一定在 |

没有标注的条目一律不是事实。

**版本漂移**：以上来源都有时间点（官方文 2026-08、指南适配 5.5.4、本机实测 5.6.2）。WorkBuddy 更新后菜单位置、模型列表、倍率都可能变。**用户眼前的界面和这里对不上时，以界面为准**，对用户说「你这版可能改了位置 / 倍率，以你界面上显示的为准」，不要坚持本文件的旧说法，也不要现编新路径。

## 扫描脚本读的是什么

`scripts/scan.py` 只读下面这些路径，全部 `本机实测` 于客户端 5.6.2 / macOS：

| 路径 | 取什么 | 用于 |
|---|---|---|
| `~/.workbuddy/workbuddy.db` → `session_usage(used, size)` | 会话上下文已用量与窗口上限——**就是上下文圈那两个数** | L3 |
| 同库 `sessions(mode, model, context_window, cwd, title)` | 当前会话的模式、模型、窗口、工作空间 | L4 / L5 |
| 同库 `workspaces(path)` | 工作空间路径，据此统计文件数 | L2 |
| `~/.workbuddy/skills/` | 已安装技能数 | L2 |
| `~/.workbuddy/settings.json` → `skillOverrides` | 值为 `user-invocable-only` 的技能＝已设为不常驻 | L2 |
| 同文件 `enabledPlugins` | 启用的插件数 | L2 |
| `~/.workbuddy/mcp-tool-list.json` → `entries` | MCP 服务数与工具定义总数 | L2 |

**这些结构没有官方文档背书，是实测得来的。** 换个客户端版本或平台就可能对不上，所以：

- 脚本以只读方式打开，复制到临时目录再读，**绝不写回**
- 任何一项读不到就跳过该项，不报错、不中断
- 找不到 `~/.workbuddy` 直接退出码 `2`，由 SKILL.md 退回问答式诊断
- **不许把这些路径当成「WorkBuddy 的官方数据格式」讲给用户听**

### 口径（别误读）

| 字段 | 它是什么 | 别当成什么 |
|---|---|---|
| `session_usage.used` | **当前上下文的输入 token**。实测与该会话 jsonl 里的峰值 `inputTokens` **三次完全相等**（79061／50835／87939），可以直接当上下文占用用 | 不是累计消耗，也不是存储字节 |
| `session_usage.size` | **这个会话的预算**（实测见过 200000 / 300000） | **不是模型上限**，不同会话不一样，**不许跨会话比百分比** |
| 安装计数 | 技能／插件／MCP 工具定义的**个数** | **不是**上下文圈里那四项的占比。个数多 ≠ 那项占比最大 |

> 网上有资料称 `used/size` 是「存储记账、与 token 用量对不上」。**实测不成立**——三个会话逐一比对 jsonl 的 `providerData.usage.inputTokens`，数值完全一致。该说法可能针对其他版本，本 skill 以实测为准。

**扫描读不到的三项**：上下文圈的**分项占比**（界面端算的，本地没有）、Max 模式开关、当前场景模式（`sessions.session_settings` 实测为空）。这三项只能问用户，且只在必要时问。

### 「改完了」不等于「省到了」

关技能、改配置之后，**当前会话不会自动变轻**。要确认真的生效，必须**新开一个会话**再看一次占用。给用户处方时要把这句带上，否则他改完发现没变化就会认为诊断错了。

## 上下文用量圈

**位置**：对话框右下角的灰色小圈。`官方`

**点开后能看到六项**（这是本 skill 最强的诊断工具，逐项照抄）：

1. 当前上下文的使用比例
2. 已使用量和模型窗口上限
3. **系统提示词占用**
4. **工具及子智能体占用**
5. **对话消息占用**
6. **连接器、MCP 及技能占用**

`官方`

**读数怎么解释**：形如「4.9% · 49.4K/1000K」，表示当前会话已用约 49.4K token，**该模型的上下文窗口上限是 1000K**。`官方`

> 所以分母**就是当前所选模型的窗口上限**，可以这样告诉用户。但**不同模型的窗口上限不一样**，不许把某一次看到的分母当成「WorkBuddy 的上限」跨模型断言。

**红线**：用量保持在**一半左右**最好；**超过一半就该考虑压缩上下文或新开任务**。`官方`

### 上下文与会话

| 功能 | 位置 / 原文 | 出处 |
|---|---|---|
| 上下文用量圈 | 见上一节 | `官方` |
| `/compact` | 对话框里直接发这条斜杠指令。把当前上下文交给模型**主动压缩**——总结前面聊过的内容、替换掉原始对话记录、腾出窗口继续跑 | `官方` |
| 压缩的有损性 | 压缩**不是完全无损的**——细节、特殊约束和中间状态都可能在总结时被弱化。但主动压缩比等窗口接近上限后被动裁剪更可控 | `官方` |

| Max 模式 | **模型选择下拉的顶部**。打开＝不压缩，保留完整上下文，适合需要长期记忆的复杂任务，**但可能增加积分消耗**；关闭＝WorkBuddy 会在某个时机自动帮你压缩上下文，降低窗口使用 | `官方` |

| 设置 → 个性化 | 手动设置：回复风格和语调（专业严谨／亲和友善／直言不讳／高效务实）、是否显示加载过程欢迎语、是否展示文件变更的过程详情、应用于所有对话的自定义指令 | `官方` |

## 官方错误码

**用户报得出错误码，就不用走问诊了。** 出处 `guide:troubleshooting.md:185-202`。

| 错误码 | 含义 | 官方处置 |
|---|---|---|
| `11115` | **输入内容过长** | 精简输入内容，或切换支持更大上下文的模型 |
| `6003` / `6004` | 请求频率受限 | 切换模型重试 |
| `1001` / `14003` | 模型侧状态异常 | 切换模型重试 |
| `11133` / `11134` | 模型侧状态异常 | 新开会话或切换模型重试 |
| `3002` / `3003` / `3007` | 网络环境（公司/家庭网络限制） | 公司网找 IT；或关闭网络代理（建议「跟随系统」） |

**归类速记**：`1xxxx / 14003` → 模型侧；`3xxx` → 网络；`60xx` → 频率受限；`11115` → 输入过长。

### 连接器 / MCP 侧的 HTTP 码

出处 `guide:02-connector-troubleshooting.md:179-189`。

| 码 / 现象 | 原因 | 处置 |
|---|---|---|
| `401` | 认证 token 过期 | 在 WorkBuddy UI → 连接器 → 重新授权 |
| `403` | 权限不足 | 检查账号是否开通该服务权限 |
| `404` | URL 路径错误或服务下线 | 检查 URL、确认服务是否存活 |
| `429` | 请求频率过高被限流 | 降低调用频率，**增加请求间隔 2-3 秒** |
| `500` / `502` / `503` | 服务端内部错误 | **等待 2-5 分钟后重试**，仍失败则服务可能已下线 |
| `连接超时` | 网络不通或服务响应慢 | 检查防火墙，**timeout 调到 600000**（10 分钟） |

部分服务的 token 需要定期刷新（通常 2 小时）；百度网盘的 `access_token` 有效期通常 30 天。`guide:02-connector-troubleshooting.md:338,344`

## 模型与倍率

出处 `guide:08-glossary.md:100-112`、`guide:12-faq.md:107`、`guide:14-scene-modes.md:112`。

| 场景 | 推荐模型 | 倍率 |
|---|---|---|
| 不确定选什么 | Auto | 0.40x |
| 批量 / 轻量任务 | Hy3 preview | 0.04x |
| 编程任务 | Deepseek V4-Pro | 0.25x |
| 长文档分析 | Kimi-K2.6 | 0.59x |
| 中文写作 / 复杂推理 | GLM-5.1 | 1.06x |
| 性价比折中 | MiniMax M2.7 | 0.26x |
| 看图理解 | GLM-5v-Turbo | 0.95x |

- 倍率 = 相对基准消耗的倍数，`0.40x` = 消耗基准的 40%
- **模型和倍率调整最频繁**：给用户时说「按指南时点的倍率」，并让他以模型下拉里当前显示的为准
- **Thinking Mode** 开启后消耗更多积分（`guide:08-glossary.md:93`）
- **专家团消耗是单专家的 3-5 倍**（`guide:12-faq.md:185`）
- 外部接入的模型消耗个人 API 额度，**不消耗 WorkBuddy 积分**（`guide:08-glossary.md:118`）

## 任务规模与会话容量

**这不是对产品好坏的评价，是一个容量判断**：一次任务需要同时顾及的文件和约束，超过单次会话能稳定携带的量时，表现就是反复读文件、反复确认、来回试。

| 任务规模 | 怎么安排 |
|---|---|
| 单个文件、几处改动、一个脚本、一个网页 | 一个会话跑完 |
| 涉及多个模块、大规模重构、要通盘设计 | **拆成多个任务**，每个任务单独一个会话，用检查点文件串联（见 [playbook.md](playbook.md) 动作 D） |

**不要在这一层下「这个产品行不行」的判断。** 用户问的是怎么变快，不是要一份产品测评。给出「怎么拆」就够了。

**已知的资源/干扰来源**：

- **技能装太多**：每个技能的定义都要发给模型，模型需要理解装了哪些技能、各自干什么、何时调用。装得越多，光是承载这些说明就要占掉一块窗口，同时模型选择时的干扰也更大。`官方`
- **连接器、MCP 及技能**在上下文圈里是**独立的一项占用**。`官方`
- **工作空间文件太多**：AI 按文件名和路径匹配，文件太多会增加干扰（`guide:12-faq.md:241-243`）
- **长会话**：上下文被稀释，可能导致 AI「忘记」前面的内容（`guide:12-faq.md:235`）

## 不许说的东西

下面这些是**基线实测中，没有本 skill 的 agent 真实编出来的东西**：

| 编造样本 | 为什么危险 |
|---|---|
| 「去设置里找『排除目录 / 忽略文件』」 | 不在白名单。用户会真去翻设置 |
| 「关掉『自动跑测试 / 自动 lint』开关」 | 不在白名单 |
| 「关掉『自动提交 / 自动分支』开关」 | 不在白名单 |
| 「日常用『快速档』，别用『深度档』」 | 档位名称是编的。真实的是 Max 模式和模型倍率 |
| 「大概率四十分钟能降到几分钟量级」 | 无依据的效果承诺 |
| 「WorkBuddy 和 CodeBuddy 积分互通」 | 零支撑。这是本 skill 自己曾经犯的错 |

**还有两条长期禁令：**

- **不许给 L6 编成因。** 「服务端排队」「高峰期更慢」「内容审查 / 合规链路拖慢响应」这类说法都只有体感，没有可复现的测量方法，官方文和指南也都没有。L6 只说「客户端侧调不动」，不解释为什么慢，也不建议用户「挪到低峰时段」——那条建议本身就建立在没依据的成因上。
- **不许建议用户改用别家产品，也不许对 WorkBuddy 做产品测评式的优劣判断。** 用户来问的是怎么把手上这件事跑顺，给出可执行的调整就够了。
