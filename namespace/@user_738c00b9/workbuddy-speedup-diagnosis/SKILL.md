# WorkBuddy 提速诊断

**核心判断：WorkBuddy 的「慢」，多数不是模型慢。最高频的三个真因是「场景/任务放错了」「上下文越背越重」「该压缩时没压缩」。**

| 什么时候读 | 文件 |
|---|---|
| 用户问的是一个具体问题（要不要压缩、Max 开不开、技能删不删……），不是报「慢」 | [reference/faq.md](reference/faq.md) —— 现成答案，直接转述 |
| 定出层之后要这一层的判据和处方 | [reference/layers.md](reference/layers.md) —— 只读那一层 |
| 要给用户一步步的操作 | [reference/playbook.md](reference/playbook.md) |
| 要说任何功能名、菜单路径、数字之前 | [reference/product-facts.md](reference/product-facts.md) —— **查不到就不说** |

## 60 秒上手

**整份技能只做一件事：把「慢」定位到一个原因，然后只动那一处。** 五步，从上往下第一个能走通的就走：

1. **报了错误码** → 查下面的错误码表，直接给处置
2. **把用户原话原样喂给脚本**：`python3 scripts/scan.py --symptom "原话" --baseline` —— 一次扫完六层，给出「结论 / 动作 / 依据」三行，并顺手存下改前基线
3. **讲成人话**：不超过 5 行，只讲一条，措辞照脚本给的档位（「就是」／「大概率是」），不自己改强
4. **脚本跑不起来（退出码 2）** → 用下面的路由表从原话找原因；还找不到就只问一个问题
5. **用户回来说没效果** → 走「第二轮」，最多三步收口

## 六条硬规矩

1. **先把原话喂给脚本，不要反问**；脚本读不到的只有圈内分项占比、Max 模式、场景模式三项
2. **层号 L1~L6 只给你自己路由用，不说给用户**；对用户用下面「说人话」那张表里的说法
3. **给处方的同时存基线**（`--baseline`），改完再跑一次拿实测降幅
4. 只说 product-facts.md 白名单里的功能名、菜单路径、数字；**界面和白名单对不上时以界面为准**，如实说「你这版可能改了位置」
5. 只说「会看到什么变化」，不承诺提速幅度
6. `/compact` 之前先让用户存检查点（六项写进工作空间文件）

## 错误码：报得出码就不用问诊

| 码 | 是什么 | 处置 |
|---|---|---|
| `11115` | 输入内容过长 | 精简输入，或换支持更大上下文的模型 |
| `6003` `6004` | 请求频率受限 | 切换模型重试 |
| `1001` `14003` | 模型侧异常 | 切换模型重试 |
| `11133` `11134` | 模型侧异常 | 新开会话或切换模型重试 |
| `3002` `3003` `3007` | 网络环境 | 查网络 / 关代理（建议「跟随系统」） |

表外的码如实说「没有公开说明」，然后走反馈。**错误码只给这一件事定案**；同一句话里的其他症状（「又慢又费积分」）照常喂脚本。

## 第一轮：跑脚本，讲一条

```bash
python3 scripts/scan.py --symptom "用户的原话" --baseline
```

脚本匹配原话 + 读本机数据（会话用量、常驻技能/插件/MCP、工作空间规模、模式、模型）+ 交叉验证，输出：

```
[*] 结论：就是／大概率是 <一句话>
[>] 现在做这一件事：<一个动作>
[=] 依据（实测数据／代理判据／症状描述）：<凭什么这么判>
[六层一览] 场景:待测  常驻开销:可疑  会话堆积:已排除 ……
```

把它讲成人话，**五个要点**：

1. **只讲 `[*]` 那一条**，措辞档位照抄。`[~] 顺带发现` 留给第二轮，这一轮不提——列两条等于没结论
2. **用 `[六层一览]` 里的「已排除」省掉用户的试错**：一句「会话太长这个原因我已经顺带查过，没问题」，用户就不用自己一项项去试
3. **处方点名**：`[占地方的技能]` 行给了最大的三个技能，直接说名字，不说「关掉不用的技能」
4. **讲出起步开销**：`[起步开销]` 行那句「每开一个新会话，一个字还没说就先背着约 N token」是全场最有说服力的一句
5. **告诉用户改完怎么验证**：改完新开一个会话，你再跑一次脚本（不带 `--baseline`），它会打出 `[对比] 起步占用 降了 X%`

**回复形状**：结论一行、动作一行；依据是「症状描述」时加一行说还缺什么才能坐实。不贴脚本原始输出、不提文件路径或数据库表名。

**范例**（用户说「前几轮还行，现在越聊越慢」）：

> 大概率是对话太长了——前面聊的每一轮它现在都还背着。
>
> 先让我把当前目标、已完成、重要约束、改过的文件、未解决问题、下一步这六项存进工作空间的一个文件，再发 `/compact` 压缩。顺序不能反，压缩会丢细节。
>
> 技能装得多不多这个原因我顺带查过了，不是它。压完还是慢就告诉我，我换个方向查。

### 说人话：术语对照

| 你脑子里的词 | 对用户说 |
|---|---|
| L1 场景错配 | 这活放错了场景（比如写代码却在「日常办公」） |
| L2 常驻开销 | 技能/插件/连接器开得多，每次对话一开始就背得重 |
| L3 会话堆积 | 这个对话聊太久了，前面的内容它一直背着 |
| L4 颗粒度 | 一次交代的事太多，它在原地打转 |
| L5 | 模型选择 / 积分消耗的问题 |
| L6 | 网络、代理或某个连接器的问题 |
| token / 上下文 | 它「背着」的内容量，右下角小圈显示的就是这个 |
| `/compact` | 把前面的对话压成一份摘要，腾出空间 |
| 检查点 | 一份写进文件的「进度备忘」，压缩后照着它接着干 |

## 第二轮：用户说「改完还是慢」

不重复第一轮的动作，也不开始列备选。按顺序，**每步只给一件事**：

**第 0 步 · 确认测对了**：关技能、改配置后**当前对话不会变轻**。让他新开一个会话，点开右下角小圈看「连接器、MCP 及技能」那项有没有降。没降 = 处方没生效（确认技能真关了），不是判断错了。

**第 1 步 · 给 `[~] 顺带发现` 里那条**——第一轮压着没说的第二可能。仍然只给一条。

**第 2 步 · 收口**：

```bash
python3 scripts/scan.py --symptom "他的原话" --tried "他已经做过但没用的动作" --report
```

生成的 300 字以内反馈文案**原样给用户**：

> 复制这段，左下角头像 → 帮助与反馈 → 意见反馈，记得勾「上传日志」。提交前自己核一眼描述准不准。

到这里结束。已排除的说排除了，剩下的如实说「客户端这边调不动了」，不再猜。

## 脚本给不出结论时

- **输出 `[!] 没匹配到已知的变慢模式`** → 它已附上反馈文案，照第二轮第 2 步给用户
- **退出码 `2`**（没找到 WorkBuddy 数据，或数据格式变了）→ 脚本已打印一句给用户的话；你用下表从原话找原因
- **`[提示]` 段**列出没读全的项，都不影响结论；需要时把那句人话转述给用户

### 路由表（你自己用，只说命中的那一行）

| 他说的现象 | 原因 | 让他做的那一件事 |
|---|---|---|
| 一开新会话就慢，什么都还没聊 | L2 | 技能管理页关掉不用的技能 |
| 圈里「连接器、MCP 及技能」那项最大 | L2 | 同上 |
| 圈里「对话消息」最大且已过半；前几轮快越聊越慢 | L3 | 存检查点 → `/compact` |
| 它反复读同一批文件、老问文件在哪；写代码却不在「代码开发」场景 | L1 | 对话区顶部切对场景；范围太大就拆成多个会话 |
| 一句话交代一大坨活，长时间没有中间产出 | L4 | 把第一步单独拎出来问 |
| 又慢又费积分 | L5 | 看模型下拉顶部 Max 模式是开是关 |
| 某个连接器时好时坏 | L6 | 看它返回什么码，对 layers.md 的 L6 码表 |
| 简单任务出字也慢，换模型没变化 | L6 | 走 layers.md 的 L6 四级自查 |

**原话里什么都没命中 → 只问这一个问题**：点开右下角小圈，展开看哪一项最大。这一问同时分开 L2 和 L3，信息量最大。

用户答不上或说「别问我」，才从下面挑**最多 2 个**：

1. 这次让它干的是什么活？
2. 慢成什么样？首字等很久 / 出字慢 / 转圈不动 / 卡「思考中」 / 跑一半停
3. 一直慢，还是聊到后面才慢？
4. 换模型试过吗？有变化吗？
5. 挂了知识库、传了长文档大表格、工作空间文件多吗？

定出层后，去 [layers.md](reference/layers.md) 取这一层的判据和处方。没有判据不许定性（L1 和错误码例外），细则在 layers.md 开头的「铁律」。

## 完整结论的格式

用户要一份完整诊断、或第二轮收口时，用这六项（可以写成自然段，但一项不能少）：

1. **场景判定**：命中 / 排除 / 待测 —— 依据（定性在别的层也要写 L1 为什么排除）
2. **一句话结论**：慢在哪
3. **判据**：靠什么得出的（没测过写「未验证」）
4. **处方**：只给一处的动作
5. **预期**：改完应该看到什么变化；没变化说明判断错了，回哪里
6. **改不了的部分**：有就直说

## 常见坑（一张表看全）

出现左列的念头就停，按右列改。

| 你正准备…… | 为什么错 | 改成 |
|---|---|---|
| 先问用户几个问题 / 甩一张问题清单 | 用户是来解决问题的，不是来填表的 | 先把原话喂给脚本 |
| 一次列出好几条建议让他全试 | 试完不知道哪条生效，只会更乱 | 只给 `[*]` 那一条 |
| 把「大概率是」说成「就是」 | 代理判据和症状描述都不是实测 | 照抄脚本档位 |
| 对用户说「你这是 L3」 | 用户听不懂编号 | 用「说人话」那张表 |
| 说一个 product-facts.md 里没有的开关或菜单路径 | 编出来的功能用户找不到，信任全丢 | 查不到就说「没法确认有这个设置」 |
| 编一个窗口上限、积分额度或刷新周期 | 编一个比不给更糟 | 让他看界面或官方渠道 |
| 把某次看到的分母说成「WorkBuddy 的上限」 | 分母是当前所选模型的窗口，换模型就变 | 说「这个模型的上限」 |
| 承诺「能快一倍」 | 没兑现一次，以后一条都不信 | 说会看到什么变化，用基线对比实测 |
| 直接让他 `/compact` | 压缩有损且不可逆 | 先存检查点到文件 |
| 让他删技能 | 删了要重装，用户会抗拒 | 关开关，随时能开回来 |
| 听到 git 乱了就说「WorkBuddy 干不了」 | 代码开发场景自带 Git 分支管理和 Worktree | 先查场景 |
| 让他「把提示词写清楚点」治场景错配 | 提示词改不了场景加载的配置 | 切场景 |
| 在当前对话里验证关技能的效果 | 当前对话不会自动变轻 | 新开会话再看 |
| 用户说换模型也没用，还在聊模型 | 模型侧已经排除 | 去 L6 |
| 网络层没有任何错误码，却给出「服务端排队 / 高峰限流」这类原因 | 没有判据的猜测 | 只说「客户端这边调不动」，走反馈 |
| 用户问 WorkBuddy 和 CodeBuddy 积分是否互通 | 没有任何资料支撑 | 如实说无法确认 |
