## 功能概述

AI代码安全审计Pro是一款AI辅助的静态代码安全分析工具。基于OWASP Top 10、CWE等公开安全标准，结合大模型对代码上下文的理解，对代码做安全审计并给出风险提示与修复方向。**需要说明的是：本工具覆盖常见高危漏洞模式，实际检出效果取决于代码质量、上下文完整度与语言/框架类型，存在误报与漏报，所有结论需人工复核后确认。**

## 痛点与解决方案

| 痛点 | 解决方案 | 对应能力 |
|------|---------|---------|
| 不知道代码里有没有SQL注入、XSS等常见漏洞 | 基于OWASP Top 10和CWE常见弱点模式做检测，覆盖主流注入类风险 | 常见漏洞模式检测 |
| 传统SAST只报漏洞编号，不告诉你怎么修 | 每个风险给出原理分析+攻击场景+修复方向参考 | 修复方向参考 |
| 多语言项目切换成本高 | 支持多种主流编程语言，一个入口审计 | 多语言支持 |
| 只贴几行代码容易误报漏报 | 支持调用链分析，上下文越完整判断越可靠 | 上下文感知分析 |
| 业务逻辑漏洞（越权、竞态）难以发现 | 提供完整调用链与业务背景时可辅助识别，否则仅提示可疑 | 业务逻辑辅助识别 |
| 审计完不知道先修哪个 | 五级风险分级，按优先级排序 | 风险分级体系 |

```
你需要审计什么代码？

│  ├─ Java (Spring) → 重点检测注入、反序列化、权限绕过
│  ├─ Node.js (Express/Koa) → 重点检测XSS、注入、原型链污染
│  └─ PHP → 重点检测SQL注入、文件包含、RCE
├─ 前端代码 → JavaScript/TypeScript、React/Vue组件（XSS、不安全DOM操作）
├─ 系统编程 → Go/Rust/C/C++（命令注入、竞态、内存安全）
├─ 移动端 → Swift/Kotlin（不安全存储、TLS验证、组件暴露）
├─ 智能合约 → Solidity（重入、整数溢出、权限控制）
└─ 不确定语言 → 提供代码自动识别（建议手动标注语言与框架）
```

## 核心能力

- **多语言静态分析**：覆盖Python、Java、JavaScript/TypeScript、Go、Rust、C/C++、PHP、Ruby、Swift、Kotlin、Solidity、Shell等主流语言与Django/Flask/Spring/Express/Gin等常见框架。
- **常见漏洞模式检测**：注入类（SQL/NoSQL/命令/代码/模板注入）、认证授权（弱密码、硬编码凭证、JWT缺陷、权限绕过、CSRF）、数据安全（敏感信息泄露、明文存储、弱加密）、输入验证（XSS、文件上传、SSRF、开放重定向）、业务逻辑（竞态、批量攻击、越权）、依赖安全。
- **风险分级**：严重 / 高危 / 中危 / 低危 / 信息，按优先级排序。
- **修复方向参考**：每个风险附原理、攻击场景、修复思路与官方规范链接（CWE/OWASP）。

## 审计维度与识别程度（定性，非实测指标）

> 下表为各类风险的相对识别难度与可靠度的定性说明，**不代表经实测验证的检出率**；实际效果取决于代码质量与上下文，需人工复核。

| 安全领域 | 检测项 | 可靠度定性说明 |
|---------|-------|--------|
| 注入攻击 | SQL/NoSQL/命令/代码/模板注入 | 模式较典型，结合上下文时识别相对可靠 |
| 身份认证 | 密码安全、JWT、会话管理 | 常见缺陷可识别，复杂认证逻辑需人工判断 |
| 访问控制 | 越权、权限配置、接口鉴权 | 依赖鉴权上下文，片段代码下易漏报 |
| 数据保护 | 加密、敏感信息、隐私合规 | 常见硬编码/弱加密可提示 |
| 输入验证 | XSS、上传、SSRF、重定向 | 典型场景可识别，框架特有机制需说明 |
| 配置安全 | 错误配置、安全头、CORS | 需结合配置上下文，仅审计代码本身 |
| 依赖安全 | 漏洞依赖、版本风险 | 参考公开漏洞信息，以官方数据为准 |
| 业务逻辑 | 竞态、批量、逻辑绕过 | 最依赖业务背景，建议作为可疑提示而非结论 |

## 使用场景
代码提交前自查、上线前安全评审、安全编码学习、第三方代码引入前评估、Code Review辅助、安全培训演示。

## 使用方法
1. 粘贴需审计的代码片段或完整文件；2. 说明编程语言与框架（可选，降低误报）；3. 说明关注的风险类型（可选）；4. 生成审计报告与修复方向。**单次建议控制在约1000行以内**，更大项目按模块分批审计。

## 独立模式（降级使用）
网络受限时可降级为"独立模式"，基于内置OWASP/CWE核心规则做离线静态分析，报告中标注"⚠️ 当前为离线模式，规则库截止日期：YYYY-MM-DD，以实际为准"。局限：无法获取最新CVE模式、业务逻辑类判断能力较在线时下降、规则库不实时更新，新型漏洞检测能力受限。

## 技术标准
遵循 OWASP Top 10、CWE Top 25；参考 NIST SSDF；报告规范链接指向 CWE/OWASP 官方文档。**本工具不声明通过 OWASP Benchmark 等测试集的量化评测，相关检出效果均为定性说明。**

## 边界与限制说明

### ✅ 能做什么（核心能力）
常见漏洞模式静态识别、多语言覆盖、修复方向参考、五级风险分级、安全编码教育。

### ❌ 不能做什么（明确局限）
1. **不能100%检出所有漏洞**：复杂业务逻辑、需深度上下文、非常见模式的漏洞可能漏报，同时存在误报。
2. **不能检测运行时问题**：静态分析无法覆盖运行时才触发的竞态、环境配置等问题。
3. **不能审计二进制/编译后代码**：需要源代码。
4. **不能替代专业渗透测试与合规审计**：本工具为辅助筛查，正式安全评估需人工渗透测试与有资质机构。
5. **不保证修复代码可直接使用**：修复方案为通用示例，需结合项目调整并测试。
6. **不支持完整项目级全量扫描**：大型项目需分批审计。

### 检出效果定性说明（非实测指标）
- 本工具**未提供经第三方测试集验证的检出率/误报率数值**；注入类等模式较典型的风险识别相对可靠，业务逻辑类最依赖上下文。
- 实际效果受代码完整性、上下文充分性、框架类型影响；提供的代码越完整，判断越可靠。
- 所有"严重/高危"结论均应人工确认真实性后再修复。

### 已知盲点
复杂业务逻辑（越权、支付流程）、并发竞态时序、复杂密码学实现缺陷、微服务跨服务调用、配置文件/环境变量中的敏感信息、0day与新型攻击手法。

## P2① 错误处理 / 重试 / 降级 / 边界说明

本节为文档级使用指引（不引入需独立运行的脚本），与上文「独立模式」「边界与限制」配合阅读。

### 错误处理
- **空/过短输入**：不臆造结论，明确提示"未检测到代码内容 / 代码过短，需足够上下文"；过短代码仅给信息级初步提示并标注置信度低。
- **超长输入（>约1000行）**：自动按"入口/认证授权/数据操作"重点区域优先审计，报告标注"已采用重点区域优先策略，整体置信度下调"，不假装完成全量深扫。
- **无法识别语言 / 语法不完整**：先尝试自动识别，失败则请求用户标注语言；对语法混乱输入提示"可能影响准确性，建议提供可编译代码"，不把猜测当确定结论。
- **非代码文本**：直接提示"似乎不是源代码"，引导正确输入。

### 重试
- **同段代码多次审计结果不一致**：以风险等级最高的一次为参考并优先人工确认高危项；若反复波动且置信度均低，应补充更完整上下文与业务背景后重审，而非采信单次输出。
- **低置信度判断**：在条目上显式标注"（低置信度，建议人工确认）"并给出判断依据，必要时建议结合多种工具交叉验证。

### 降级
- **网络/规则库不可用**：降级为「独立模式」并在报告标注离线状态与规则库截止日期（YYYY-MM-DD，以实际为准），能力降级但不中断基本筛查。
- **上下文不足导致无法判定**：标注为"可疑"并说明缺失的上下文（如鉴权中间件、路由配置），而不是强行定级。

### 边界（再次明确）
本工具为 **AI 辅助的教育/筛查参考**：**不提供经实测的检出率承诺**，覆盖常见高危模式即可，**不替代专业 SAST 工具、人工渗透测试与资质机构的合规报告**；修复代码需结合项目实际测试后再合入。
