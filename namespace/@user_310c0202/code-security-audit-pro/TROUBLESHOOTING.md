# 排障指南（TROUBLESHOOTING）

本文档帮助您快速定位和解决使用AI代码安全审计Pro时遇到的常见问题。

## 错误码速查表

| 错误码 | 错误名称 | 触发场景 | 解决方案 |
|--------|---------|---------|---------|
| CSA-E001 | 代码内容为空 | 未提供任何代码内容 | 提供需要审计的代码片段或完整文件 |
| CSA-E002 | 代码过短 | 输入代码少于10行或50个字符 | 提供完整的函数或模块代码，确保有足够上下文 |
| CSA-E003 | 代码超长 | 输入代码超过1000行 | 按文件或功能模块分批审计，或提供核心模块单独审计 |
| CSA-E004 | 语言无法识别 | 无法自动识别编程语言 | 在输入中标注代码语言（如Python、Java、Go等） |
| CSA-E005 | 代码格式不规范 | 代码格式混乱、缩进异常、语法不完整 | 提供完整可编译的代码，修正格式和语法错误 |
| CSA-E006 | 非代码输入 | 输入为纯自然语言或配置文件 | 提供需要审计的源代码而非其他内容 |
| CSA-E007 | 漏洞置信度低 | 某漏洞判断置信度较低 | 标注"低置信度，建议人工确认"并人工复核 |
| CSA-E008 | 严重程度不确定 | 无法确定漏洞的严重程度 | 标注为"可疑"并给出进一步排查建议 |
| CSA-E009 | 离线模式规则过期 | 独立模式下漏洞规则库截止日期过旧 | 联网后重新审计获取最新漏洞模式 |
| CSA-E010 | 多次审计结果不一致 | 同一代码多次审计结果有波动 | 以风险等级最高结果为参考，提供更完整上下文后重审 |

## 常见问题排查

### 问题1：审计结果误报较多

**现象**：审计报告中标出了很多漏洞，但人工检查后发现大部分是误报。

**原因**：常见于代码上下文不完整、未说明框架、或框架内置安全机制未被识别。

**解决方案**：
1. 提供更完整的代码上下文，包括输入来源、中间处理、输出去向
2. 说明使用的框架（如Django、Spring、Express、Gin等），帮助识别框架自带安全特性
3. 先过一遍漏洞列表，结合业务场景判断真实性
4. 高危漏洞优先确认，中低危漏洞批量评估
5. 建立自己的误报案例库，逐步优化判断效率

### 问题2：审计结果提示"已采用重点区域优先审计策略"

**现象**：审计报告显示"⚠️ 输入代码较长（共XXXX行），已采用重点区域优先审计策略。"

**原因**：输入代码超过1000行，触发了自动分段审计策略。

**解决方案**：
1. 核心模块（入口函数、认证授权、数据操作）已优先深度审计
2. 如需全量深度审计，建议按模块分批提供代码
3. 对关键模块单独提供完整代码进行专项审计
4. 长代码审计的整体置信度会适当下调

### 问题3：无法识别编程语言

**现象**：提示"⚠️ 无法自动识别编程语言"

**原因**：代码特征不明显或代码格式混乱导致语言识别失败。

**解决方案**：
1. 在输入中明确标注编程语言（如"语言：Python / Flask"）
2. 说明使用的框架（如Django、Spring、Express等），提升审计准确率
3. 确保代码格式规范，避免缩进异常和语法错误

### 问题4：业务逻辑漏洞检测不准确

**现象**：越权、竞态条件等业务逻辑漏洞未被检出或误报较多。

**原因**：业务逻辑漏洞需要理解完整业务流程和并发场景，仅靠片段代码时最易漏报或误报（本工具不提供实测检出率数值，此类问题应作为可疑提示并人工复核）。

**解决方案**：
1. 提供完整的调用链：路由层+控制层+服务层的完整代码
2. 说明业务背景和鉴权逻辑
3. 提供路由配置和中间件代码
4. 对于关键业务逻辑，结合人工安全审计交叉验证

### 问题5：修复代码不适用于项目

**现象**：审计报告中的修复代码示例无法直接应用到项目中。

**原因**：修复代码基于通用安全最佳实践生成，可能未考虑项目特殊逻辑和依赖。

**解决方案**：
1. 把修复方案作为参考方向，理解修复原理
2. 结合项目实际架构和技术栈调整修复代码
3. 修复后充分测试（功能测试+安全测试）
4. 关键模块的安全修复建议安排Code Review
5. 不要直接复制粘贴，根据项目实际情况改写

### 问题6：多次审计结果不一致

**现象**：同一段代码多次审计，漏洞数量或详情有变化。

**原因**：AI审计具有随机性，不同次审计可能关注不同的代码路径。

**解决方案**：
1. 以风险等级最高的一次结果为参考，优先确认高危漏洞
2. 提供更完整的代码上下文和业务背景后重新审计
3. 人工排查可疑漏洞，结合业务场景判断真实性
4. 对于关键系统的核心代码，结合多种审计工具交叉验证
5. 将该代码片段加入测试用例库，用于后续优化

## 性能优化建议

1. **单次审计控制在1000行以内**：达到最优的检测深度和准确率
2. **提供完整代码上下文**：包括输入来源、中间处理、输出去向，减少误报
3. **说明编程语言和框架**：帮助识别框架安全特性，提升准确率
4. **大型项目按模块分批审计**：避免触发分段策略，确保全量检测
5. **优先审计核心模块**：入口函数、认证授权、数据操作相关代码优先
6. **高危漏洞优先确认修复**：不要按顺序逐个看，先处理严重和高危项
