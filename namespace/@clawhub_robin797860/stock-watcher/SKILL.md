## 🔴 数据获取路径（最重要，先读这一节）

本技能**不附带任何脚本**。所有数据必须通过以下渠道之一获取，**并在输出中标注来源**。

### 优先级顺序

| 顺序 | 渠道 | 适用 |
|---|---|---|
| 1 | 内置金融数据工具（行情、财报、资金流、板块） | 行情、财务、资金流、板块 |
| 2 | 联网检索（财经门户、交易所公告、公司 IR 页、SEC EDGAR） | 公告、新闻、研报、传闻核查 |
| 3 | 用户提供的文件（持仓对账单 CSV/XLSX、板块清单） | 持仓、组合、成本价 |
| 4 | 用户口述 | 持仓数量、成本价等私有信息 |

### 🔴 CHECKPOINT（每次开工前必做）

1. **确认取数渠道可用**：内置工具是否可用？网络是否通？文件是否可读？
2. **任一渠道不可用时 → 立刻告知用户**，并说明哪些字段拿不到。**禁止用记忆中的旧价格、上一交易日数据或估算值代替。**
3. **禁止编造**：任何数字（价格、成交量、财务指标、新闻）都必须有实际来源。无来源就写「数据缺失」。

### 行情代码格式

| 市场 | 格式 | 示例 |
|------|------|------|
| 沪A | 6位（60/68开头） | `600519` 贵州茅台 |
| 深A | 6位（00/30 开头） | `000001` 平安银行 |
| 创业板 | 6位（30开头） | `300750` 宁德时代 |
| 港股 | 5位数字 | `00700` 腾讯控股 |
| 美股 | 字母 | `AAPL` 苹果 |

用户说「茅台」这类名称时，**先确认代码再取数**，不要把名称当代码用。

## ⚡ 核心规则

### 时间约束
- 单次响应目标 ≤ 5 分钟；取数超时即降级，不反复重试
- 非交易时段：明确标注「以下为最近交易日（X月X日）收盘数据」
- K线默认取近 60 根（日K），减少计算量

### 执行策略
- 能并行的取数请求并行发出
- 排行榜默认返回 TOP10，不返回 TOP20
- 一次对话只做一件事：不要在同一回复里既分析个股又扫全市场

### ❌ 不要做的事
|❌ 禁止 | 原因 |
|--------|------|
| 给出「一定涨」「包赚」「必涨」等绝对化判断 | 无任何技术指标能保证结果 |
| 把未核实传闻当利好/利空计入结论 | 传闻证伪率高|
| 把抓不到的字段用估值/估算填满报告 | 等于制造虚假确定性 |
| 输出英文原始报错或堆栈信息 | 应用友好中文说明 |
| 非交易时段反复重试取数 | 直接用最近交易日数据并标注 |
| 声称已生成图表/文件而实际未生成 | 必须真实产出或明说做不到 |
| 自动建立用户交易档案或持仓库 | 只在用户主动要求时记录 |
| 单次对话中重复请求同一只股票超过 2 次 | 无意义消耗 |

## 🔧 错误处理

取数或计算出错时，**绝不直接输出英文报错或堆栈信息**。按下表转译：

| 情况 | 友好中文提示 |
|------|------------|
| 网络请求失败/超时 | 「网络不太稳定，本次数据获取失败。请稍后重试或检查网络连接。」 |
| 数据格式异常 | 「数据源返回格式异常，可能是接口临时维护。建议 1 分钟后再试。」 |
| 未找到该股票 | 「没有找到「XXX」的数据。请确认：① 代码是否正确 ② 是否已退市/停牌 ③ 市场是否选对。」 |
| K线数据不足 | 「该股票K线数据不足（可能是新股或长期停牌），暂时无法做技术分析。」 |
| 财务字段缺失 | 「该数据源未提供 XX 字段，本次不做该项分析（不估算、不推测）。」 |
| 非交易时段 | 「当前非交易时段，以下为最近交易日（X月X日）收盘数据。」 |
| 绘图库不可用 | 「当前环境无法生成K线图，改为提供文字版技术摘要。」 |
| 检索被限流 | 「检索请求较频繁，请稍后再试。」 |

**兜底原则**：任何未预料的错误，统一回复：
> 「抱歉，出了点问题（错误类型：XXX）。可以尝试：① 确认股票代码 ② 稍后重试 ③ 换一只股票。」

**禁止**：为了让报告看起来完整而填充任何未经取数验证的数字。
